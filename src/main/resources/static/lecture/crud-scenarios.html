📝 수강신청 생성 (CREATE)

Step 1 (N:1 + N:1)

// 복잡한 수동 관계 설정
public EnrollmentResponse enroll(EnrollmentCreateRequest request) {
    Course course = courseRepository.findById(request.getCourseNo())
            .orElseThrow(() -> new BusinessException(ErrorCode.COURSE_NOT_FOUND));
    
    User student = userRepository.findById(request.getStudentNo())
            .orElseThrow(() -> new BusinessException(ErrorCode.USER_NOT_FOUND));
    
    // 관계 설정을 수동으로 해야 함
    Enrollment enrollment = Enrollment.builder()
            .course(course)
            .student(student)
            .build();
    
    // Course의 currentStudents도 수동으로 증가
    course.increaseCurrentStudents();
    
    return EnrollmentResponse.from(
        enrollmentRepository.save(enrollment)
    );
}

문제점:

  • • 관계 설정을 수동으로 해야 함
  • • currentStudents 증가도 수동
  • • 실수할 가능성 높음

Step 2 (1:N + N:1)

// 편의 메서드로 간단하게
public EnrollmentResponse enroll(EnrollmentCreateRequest request) {
    Course course = courseRepository.findById(request.getCourseNo())
            .orElseThrow(() -> new BusinessException(ErrorCode.COURSE_NOT_FOUND));
    
    User student = userRepository.findById(request.getStudentNo())
            .orElseThrow(() -> new BusinessException(ErrorCode.USER_NOT_FOUND));
    
    Enrollment enrollment = Enrollment.builder()
            .course(course)
            .student(student)
            .build();
    
    // 편의 메서드로 한 번에 처리
    course.addEnrollment(enrollment);
    student.addEnrollment(enrollment);
    
    return EnrollmentResponse.from(
        enrollmentRepository.save(enrollment)
    );
}

개선점:

  • • 편의 메서드로 자동 처리
  • • 양쪽 엔티티 동기화
  • • 실수 방지

✏️ 상태 변경 (UPDATE)

Step 1 (N:1 + N:1)

// 수강신청 승인
public EnrollmentResponse approve(Long enrollmentNo) {
    Enrollment enrollment = enrollmentRepository.findById(enrollmentNo)
            .orElseThrow(() -> new BusinessException(ErrorCode.ENROLLMENT_NOT_FOUND));
    
    // 상태 변경
    enrollment.setStatus(EnrollmentStatus.APPROVED);
    
    // Course의 currentStudents도 수동으로 증가
    Course course = enrollment.getCourse();
    course.increaseCurrentStudents();
    
    return EnrollmentResponse.from(
        enrollmentRepository.save(enrollment)
    );
}

문제점:

  • • 상태 변경과 currentStudents 증가를 분리해서 처리
  • • 비즈니스 로직이 분산됨
  • • 일관성 보장 어려움

Step 2 (1:N + N:1)

🗑️ 신청 취소 (DELETE)

Step 1 (N:1 + N:1)

// 수강신청 취소
public void cancel(Long enrollmentNo, User student) {
    Enrollment enrollment = enrollmentRepository.findById(enrollmentNo)
            .orElseThrow(() -> new BusinessException(ErrorCode.ENROLLMENT_NOT_FOUND));
    
    // 권한 확인
    if (!enrollment.getStudent().equals(student)) {
        throw new BusinessException(ErrorCode.ENROLLMENT_FORBIDDEN);
    }
    
    // 상태 변경
    enrollment.setStatus(EnrollmentStatus.CANCELLED);
    
    // Course의 currentStudents도 수동으로 감소
    Course course = enrollment.getCourse();
    course.decreaseCurrentStudents();
    
    enrollmentRepository.save(enrollment);
}

문제점:

  • • 취소 로직과 currentStudents 감소를 분리 처리
  • • 권한 확인 로직이 Service에 분산
  • • 코드가 길고 복잡함

Step 2 (1:N + N:1)

// 수강신청 취소
public void cancel(Long enrollmentNo, User student) {
    Enrollment enrollment = enrollmentRepository.findById(enrollmentNo)
            .orElseThrow(() -> new BusinessException(ErrorCode.ENROLLMENT_NOT_FOUND));
    
    // 편의 메서드로 한 번에 처리
    enrollment.cancel(student);
    
    enrollmentRepository.save(enrollment);
}

// Enrollment 엔티티의 편의 메서드
public void cancel(User student) {
    // 권한 확인
    if (!this.student.equals(student)) {
        throw new BusinessException(ErrorCode.ENROLLMENT_FORBIDDEN);
    }
    
    // 상태 변경 및 currentStudents 감소
    this.status = EnrollmentStatus.CANCELLED;
    this.course.decreaseCurrentStudents();
}

개선점:

  • • 비즈니스 로직이 엔티티에 집중
  • • 권한 확인도 엔티티에서 처리
  • • 코드가 간결하고 명확함

📊 개선 효과 정리

Step 1 (N:1 + N:1) 문제점

  • 1 복잡한 쿼리: Repository에 여러 쿼리 메서드 필요
  • 2 수동 관계 설정: 매번 관계를 수동으로 설정
  • 3 비즈니스 로직 분산: Service와 Entity에 로직이 분산
  • 4 실수 가능성: 관계 설정을 깜빡할 수 있음

Step 2 (1:N + N:1) 개선점

  • 1 쿼리 제거: Repository 쿼리 불필요
  • 2 편의 메서드: 자동으로 관계 설정
  • 3 로직 캡슐화: 비즈니스 로직이 엔티티에 집중
  • 4 안전성: 실수 방지 및 일관성 보장
