LazyInitializationException 해결

JPA에서 가장 자주 발생하는 문제와 해결 방법

문제란?

LazyInitializationException은 JPA에서 지연 로딩으로 설정된 연관 객체에 트랜잭션이 끝난 후 접근하려고 할 때 발생하는 예외입니다. 

org.hibernate.LazyInitializationException: 
could not initialize proxy [io.goorm.jpa.entity.Course#1] - no Session

발생 원인

  • • 트랜잭션이 끝난 후 연관 객체 접근
  • • FetchType.LAZY로 설정된 연관 객체
  • • @Transactional 범위를 벗어남

주요 발생 지점

  • • Controller에서 Service 반환 엔티티 사용
  • • JSON 변환 시 (Jackson 직렬화)
  • • @Transactional 없는 메서드에서

문제 상황

❌ 문제 코드

@Service
public class CourseService {
    public Course getCourse(Long courseNo) {
        return courseRepository.findById(courseNo)
                .orElseThrow(() -> new BusinessException(ErrorCode.COURSE_NOT_FOUND));
    }
}

@RestController
public class CourseController {
    @GetMapping("/courses/{courseNo}")
    public Course getCourse(@PathVariable Long courseNo) {
        Course course = courseService.getCourse(courseNo);
        
        // 여기서 LazyInitializationException 발생!
        System.out.println(course.getInstructor().getFullName());
        
        return course; // JSON 변환 시에도 에러 발생
    }
}

해결 방법

1. DTO 변환 (권장)

// DTO 클래스
public record CourseResponse(
    Long courseNo,
    String name,
    String description,
    String instructorName,
    List<EnrollmentResponse> enrollments
) {
    public static CourseResponse from(Course course) {
        return new CourseResponse(
            course.getCourseNo(),
            course.getName(),
            course.getDescription(),
            course.getInstructor().getFullName(),
            course.getEnrollments().stream()
                    .map(EnrollmentResponse::from)
                    .toList()
        );
    }
}

// Service에서 DTO 반환
@Service
public class CourseService {
    public CourseResponse getCourse(Long courseNo) {
        Course course = courseRepository.findById(courseNo)
                .orElseThrow(() -> new BusinessException(ErrorCode.COURSE_NOT_FOUND));
        
        return CourseResponse.from(course);
    }
}

2. Fetch Join 사용

@Repository
public interface CourseRepository extends JpaRepository<Course, Long> {
    
    @Query("SELECT c FROM Course c JOIN FETCH c.instructor WHERE c.courseNo = :courseNo")
    Optional<Course> findByIdWithInstructor(@Param("courseNo") Long courseNo);
    
    @Query("SELECT c FROM Course c JOIN FETCH c.instructor LEFT JOIN FETCH c.enrollments WHERE c.courseNo = :courseNo")
    Optional<Course> findByIdWithDetails(@Param("courseNo") Long courseNo);
}

3. @EntityGraph 사용

@Repository
public interface CourseRepository extends JpaRepository<Course, Long> {
    
    @EntityGraph(attributePaths = {"instructor"})
    @Query("SELECT c FROM Course c WHERE c.courseNo = :courseNo")
    Optional<Course> findByIdWithInstructor(@Param("courseNo") Long courseNo);
    
    @EntityGraph(attributePaths = {"instructor", "enrollments"})
    @Query("SELECT c FROM Course c WHERE c.courseNo = :courseNo")
    Optional<Course> findByIdWithDetails(@Param("courseNo") Long courseNo);
}

4. @Transactional 범위 확장

@Service
public class CourseService {
    
    @Transactional(readOnly = true)
    public Course getCourse(Long courseNo) {
        Course course = courseRepository.findById(courseNo)
                .orElseThrow(() -> new BusinessException(ErrorCode.COURSE_NOT_FOUND));
        
        // 트랜잭션 범위 내에서 연관 객체 접근
        course.getInstructor().getFullName();
        course.getEnrollments().size();
        
        return course;
    }
}

권장사항

✅ 권장

  • • DTO 사용: 엔티티 대신 DTO로 데이터 전달
  • • Fetch Join: 필요한 연관 객체는 미리 로딩
  • • @EntityGraph: 간단한 설정으로 연관 객체 로딩
  • • 지연 로딩: FetchType.LAZY 기본 사용

❌ 피해야 할 것

  • • 엔티티 직접 반환: Controller에서 엔티티 직접 반환
  • • 과도한 Eager 로딩: FetchType.EAGER 남발
  • • 순환 참조: toString()에서 연관 객체 참조
  • • 비트랜잭션 접근: 트랜잭션 없이 연관 객체 접근

설정 최적화

# application.yml
spring:
  jpa:
    properties:
      hibernate:
        # 배치 크기 설정으로 N+1 문제 완화
        default_batch_fetch_size: 100
        # 지연 로딩 프록시 초기화 설정
        enable_lazy_load_no_trans: false
    # Open Session In View 비활성화 (권장)
    open-in-view: false
