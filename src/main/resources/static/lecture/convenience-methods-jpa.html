왜 JPA에서 편의 메서드가 필요한가?

문제 상황

양방향 관계의 문제점

// 잘못된 사용법
Course course = new Course();
course.setName("JPA 강의");

Instructor instructor = new Instructor();
instructor.setName("김강사");

// 한쪽만 설정 (동기화 안됨)
course.setInstructor(instructor);

// instructor.getCourses()에는 course가 없음!
System.out.println(instructor.getCourses().size()); // 0

// 또는
instructor.getCourses().add(course);
// course.getInstructor()는 null!
System.out.println(course.getInstructor()); // null

해결책

편의 메서드로 해결

// 편의 메서드 사용
Course course = new Course();
course.setName("JPA 강의");

Instructor instructor = new Instructor();
instructor.setName("김강사");

// 편의 메서드로 한 번에 처리
course.setInstructor(instructor);

// 양쪽 모두 동기화됨
System.out.println(instructor.getCourses().size()); // 1
System.out.println(course.getInstructor().getName()); // "김강사"

편의 메서드의 필요성

동기화 자동화

  • • 양쪽 컬렉션 자동 동기화
  • • 데이터 일관성 보장
  • • 실수 방지

코드 간소화

  • • 복잡한 로직 추상화
  • • 반복 코드 제거
  • • 가독성 향상

편의 메서드 기본 패턴

기본 편의 메서드

@Entity
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long courseNo;
    
    private String name;
    private String description;
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "instructor_no")
    private Instructor instructor;
    
    // 편의 메서드: 관계 설정
    public void setInstructor(Instructor instructor) {
        if (this.instructor != null) {
            this.instructor.getCourses().remove(this);
        }
        this.instructor = instructor;
        if (instructor != null) {
            instructor.getCourses().add(this);
        }
    }
    
    // 편의 메서드: 관계 제거
    public void removeInstructor() {
        if (this.instructor != null) {
            this.instructor.getCourses().remove(this);
            this.instructor = null;
        }
    }
}

편의 메서드 핵심 원칙

  • • 양방향 동기화: 양쪽 컬렉션을 자동으로 동기화
  • • null 체크: null 값에 대한 안전한 처리
  • • 기존 관계 제거: 새로운 관계 설정 전 기존 관계 제거
  • • 일관성 보장: 항상 올바른 상태 유지

고급 편의 메서드 패턴

비즈니스 로직 포함

@Entity
public class Course {
    private String name;
    private Integer maxStudents;
    private Integer currentStudents = 0;
    
    @OneToMany(mappedBy = "course", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Enrollment> enrollments = new ArrayList<>();
    
    // 편의 메서드: 수강신청 (비즈니스 로직 포함)
    public void addEnrollment(Enrollment enrollment) {
        if (enrollment == null) {
            throw new IllegalArgumentException("Enrollment cannot be null");
        }
        
        if (this.currentStudents >= this.maxStudents) {
            throw new IllegalStateException("Course is full");
        }
        
        this.enrollments.add(enrollment);
        enrollment.setCourse(this);
        this.currentStudents++;
    }
    
    // 편의 메서드: 수강신청 취소
    public void removeEnrollment(Enrollment enrollment) {
        if (enrollment != null && this.enrollments.remove(enrollment)) {
            enrollment.setCourse(null);
            this.currentStudents--;
        }
    }
}

복합 작업

@Entity
public class Enrollment {
    @Enumerated(EnumType.STRING)
    private EnrollmentStatus status = EnrollmentStatus.PENDING;
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "course_no")
    private Course course;
    
    // 편의 메서드: 수강신청 승인
    public void approve() {
        if (this.status != EnrollmentStatus.PENDING) {
            throw new IllegalStateException("Only pending enrollments can be approved");
        }
        
        this.status = EnrollmentStatus.APPROVED;
        this.course.increaseCurrentStudents();
    }
    
    // 편의 메서드: 수강신청 거절
    public void reject(String reason) {
        if (this.status != EnrollmentStatus.PENDING) {
            throw new IllegalStateException("Only pending enrollments can be rejected");
        }
        
        this.status = EnrollmentStatus.REJECTED;
        this.reason = reason;
    }
}

  • • 에러 처리

편의 메서드 모범 사례

권장사항

  • • 관계의 주인이 아닌 쪽에 구현: mappedBy가 있는 쪽
  • • null 체크: 항상 null 값 확인
  • • 기존 관계 제거: 새로운 관계 설정 전 기존 관계 제거
  • • 비즈니스 로직 포함: 관련된 비즈니스 규칙 포함
  • • 예외 처리: 적절한 예외 메시지 제공

피해야 할 것

  • • 관계의 주인에 구현: @JoinColumn이 있는 쪽
  • • null 체크 생략: NullPointerException 발생 가능
  • • 기존 관계 무시: 중복 관계 발생 가능
  • • 비즈니스 로직 분리: 일관성 문제 발생
  • • 예외 처리 생략: 디버깅 어려움
