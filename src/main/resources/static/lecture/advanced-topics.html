비관적 락 (Pessimistic Locking)

비관적 락이란?

데이터를 읽기 전에 락을 걸어서 다른 트랜잭션이 해당 데이터를 수정하지 못하도록 하는 방식입니다. 동시성 문제를 완전히 방지하지만 성능에 영향을 줄 수 있습니다.

Repository 설정

@Repository
public interface CourseRepository extends JpaRepository<Course, Long> {
    
    @Lock(LockModeType.PESSIMISTIC_WRITE)
    @Query("SELECT c FROM Course c WHERE c.courseNo = :courseNo")
    Optional<Course> findByIdWithLock(@Param("courseNo") Long courseNo);
    
    @Lock(LockModeType.PESSIMISTIC_WRITE)
    @Query("SELECT c FROM Course c WHERE c.courseNo = :courseNo " +
           "AND c.currentStudents < c.maxStudents")
    Optional<Course> findAvailableByIdWithLock(@Param("courseNo") Long courseNo);
}

Service에서 사용

@Service
@Transactional
public class CourseService {
    
    public CourseResponse enrollStudent(Long courseNo, Long studentNo) {
        // 비관적 락으로 강의 조회
        Course course = courseRepository.findByIdWithLock(courseNo)
                .orElseThrow(() -> new BusinessException(ErrorCode.COURSE_NOT_FOUND));
        
        // 정원 확인
        if (course.getCurrentStudents() >= course.getMaxStudents()) {
            throw new BusinessException(ErrorCode.COURSE_FULL);
        }
        
        // 수강신청 처리
        User student = userRepository.findById(studentNo)
                .orElseThrow(() -> new BusinessException(ErrorCode.USER_NOT_FOUND));
        
        Enrollment enrollment = Enrollment.builder()
                .course(course)
                .student(student)
                .build();
        
        course.addEnrollment(enrollment);
        
        return CourseResponse.from(course);
    }
}

락 모드 종류

PESSIMISTIC_READ

공유 락, 읽기 전용

PESSIMISTIC_WRITE

배타 락, 읽기/쓰기

PESSIMISTIC_FORCE_INCREMENT

버전 증가와 함께 락

QueryDSL 고급 기능

통계 쿼리

@Repository
@RequiredArgsConstructor
public class CourseQueryRepository {
    
    private final JPAQueryFactory queryFactory;
    private final QCourse course = QCourse.course;
    private final QEnrollment enrollment = QEnrollment.enrollment;
    
    // 강의별 상세 통계
    public CourseStatistics getCourseStatistics(Long courseNo) {
        return queryFactory
                .select(Projections.constructor(CourseStatistics.class,
                        course.courseNo,
                        course.name,
                        course.maxStudents,
                        course.enrollments.size().as("totalEnrollments"),
                        course.enrollments.size().as("approvedEnrollments")
                ))
                .from(course)
                .where(course.courseNo.eq(courseNo))
                .fetchOne();
    }
    
    // 강사별 강의 통계
    public List<CourseStatistics> getInstructorStatistics() {
        return queryFactory
                .select(Projections.constructor(CourseStatistics.class,
                        course.instructor.userNo,
                        course.instructor.fullName,
                        course.courseNo.count().as("totalCourses"),
                        course.maxStudents.sum().as("totalCapacity"),
                        course.enrollments.size().sum().as("totalEnrollments")
                ))
                .from(course)
                .where(course.deleted.eq(false))
                .groupBy(course.instructor.userNo, course.instructor.fullName)
                .orderBy(course.courseNo.count().desc())
                .fetch();
    }
}

동적 검색

// 공통 조건 모듈
public class CourseSearchCondition {
    private String courseName;
    private String instructorName;
    private Integer minStudents;
    private Integer maxStudents;
    private LocalDateTime startDate;
    private LocalDateTime endDate;
}

// 동적 검색 쿼리
public Page<Course> searchCourses(CourseSearchCondition condition, Pageable pageable) {
    List<Course> content = queryFactory
            .selectFrom(course)
            .leftJoin(course.instructor, user).fetchJoin()
            .where(
                    courseNameContains(condition.getCourseName()),
                    instructorNameContains(condition.getInstructorName()),
                    minStudentsGoe(condition.getMinStudents()),
                    maxStudentsLoe(condition.getMaxStudents()),
                    startDateGoe(condition.getStartDate()),
                    endDateLoe(condition.getEndDate())
            )
            .orderBy(course.createdAt.desc())
            .offset(pageable.getOffset())
            .limit(pageable.getPageSize())
            .fetch();
    
    long total = queryFactory
            .selectFrom(course)
            .where(
                    courseNameContains(condition.getCourseName()),
                    instructorNameContains(condition.getInstructorName()),
                    minStudentsGoe(condition.getMinStudents()),
                    maxStudentsLoe(condition.getMaxStudents()),
                    startDateGoe(condition.getStartDate()),
                    endDateLoe(condition.getEndDate())
            )
            .fetch()
            .size();
    
    return new PageImpl<>(content, pageable, total);
}

조건 메서드

// BooleanExpression을 활용한 조건 메서드
private BooleanExpression courseNameContains(String courseName) {
    return courseName != null ? course.name.containsIgnoreCase(courseName) : null;
}

private BooleanExpression instructorNameContains(String instructorName) {
    return instructorName != null ? course.instructor.fullName.containsIgnoreCase(instructorName) : null;
}

private BooleanExpression minStudentsGoe(Integer minStudents) {
    return minStudents != null ? course.currentStudents.goe(minStudents) : null;
}

private BooleanExpression maxStudentsLoe(Integer maxStudents) {
    return maxStudents != null ? course.currentStudents.loe(maxStudents) : null;
}

배치 처리와 성능 최적화

수강신청 일괄 처리

@Service
@Transactional
public class EnrollmentService {
    
    public BatchProcessResult processBatchEnrollments(BatchEnrollmentRequest request) {
        List<Long> enrollmentIds = request.getEnrollmentIds();
        BatchAction action = request.getAction();
        String reason = request.getReason();
        
        List<Enrollment> enrollments = enrollmentRepository
                .findPendingByIdsForBatchUpdate(enrollmentIds);
        
        if (enrollments.isEmpty()) {
            throw new BusinessException(ErrorCode.NO_PENDING_ENROLLMENTS);
        }
        
        List<Enrollment> successList = new ArrayList<>();
        List<EnrollmentError> errorList = new ArrayList<>();
        
        for (Enrollment enrollment : enrollments) {
            try {
                if (action == BatchAction.APPROVE) {
                    enrollment.approve();
                } else if (action == BatchAction.REJECT) {
                    enrollment.reject(reason);
                }
                successList.add(enrollment);
            } catch (Exception e) {
                errorList.add(new EnrollmentError(
                        enrollment.getEnrollmentNo(),
                        e.getMessage()
                ));
            }
        }
        
        return new BatchProcessResult(successList.size(), errorList);
    }
}

@EntityGraph 활용

@Repository
public interface CourseRepository extends JpaRepository<Course, Long> {
    
    @EntityGraph(attributePaths = {"instructor", "enrollments"})
    @Query("SELECT c FROM Course c WHERE c.courseNo = :courseNo")
    Optional<Course> findByIdWithDetails(@Param("courseNo") Long courseNo);
    
    @EntityGraph(attributePaths = {"instructor"})
    @Query("SELECT c FROM Course c WHERE c.deleted = false")
    List<Course> findAllAvailableCourses();
}

// Service에서 사용
@Service
public class CourseService {
    
    public CourseResponse getCourseWithDetails(Long courseNo) {
        Course course = courseRepository.findByIdWithDetails(courseNo)
                .orElseThrow(() -> new BusinessException(ErrorCode.COURSE_NOT_FOUND));
        
        return CourseResponse.from(course);
    }
}

N+1 문제 해결

문제 상황

// N+1 문제 발생
List<Course> courses = courseRepository.findAll();
for (Course course : courses) {
    System.out.println(course.getInstructor().getFullName()); // 추가 쿼리 발생
}

해결 방법

// @EntityGraph로 해결
@EntityGraph(attributePaths = {"instructor"})
List<Course> courses = courseRepository.findAll();

// 또는 Fetch Join 사용
@Query("SELECT c FROM Course c JOIN FETCH c.instructor")
List<Course> findAllWithInstructor();

@EntityGraph 상세

@EntityGraph의 장점

  • • 간단한 설정: 복잡한 JPQL 대신 간단한 어노테이션
  • • 가독성: 코드의 의도가 명확하게 드러남
  • • 유지보수: 엔티티 구조 변경 시 자동 반영
  • • 성능: N+1 문제를 효과적으로 해결

기본 사용법

@EntityGraph(attributePaths = {"instructor"})
@Query("SELECT c FROM Course c WHERE c.deleted = false")
List<Course> findAvailableCourses();

// 여러 관계를 한 번에
@EntityGraph(attributePaths = {"instructor", "enrollments", "curriculums"})
@Query("SELECT c FROM Course c WHERE c.courseNo = :courseNo")
Optional<Course> findByIdWithAllDetails(@Param("courseNo") Long courseNo);

성능 최적화 팁

권장사항

  • • 지연 로딩: FetchType.LAZY 기본 사용
  • • @EntityGraph: 필요한 경우에만 사용
  • • 배치 크기: default_batch_fetch_size 설정
  • • 인덱스: 자주 조회하는 컬럼에 인덱스 생성
  • • DTO 변환: 엔티티 대신 DTO 사용

주의사항

  • • 과도한 조인: 너무 많은 관계를 한 번에 로딩하지 말 것
  • • 메모리 사용량: 대량 데이터 처리 시 주의
  • • 트랜잭션 범위: 적절한 트랜잭션 범위 유지
  • • 캐시 고려: 자주 조회하는 데이터는 캐시 활용
