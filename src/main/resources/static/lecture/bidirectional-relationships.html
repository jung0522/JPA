양방향 관계란?

정의

양방향 관계는 두 엔티티가 서로를 참조할 수 있는 관계입니다. 한쪽에서 다른 쪽으로, 다른 쪽에서도 한쪽으로 접근이 가능합니다.

핵심: 양쪽에서 서로를 참조할 수 있음

양방향 관계 예시

// Course ↔ Instructor (양방향)
@Entity
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long courseNo;
    
    private String name;
    private String description;
    
    // Course → Instructor
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "instructor_no")
    private Instructor instructor;
    
    // Course ← Instructor (양방향)
    @OneToMany(mappedBy = "instructor")
    private List<Course> courses = new ArrayList<>();
}

@Entity
public class Instructor {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long instructorNo;
    
    private String name;
    private String email;
    
    // Instructor ← Course (양방향)
    @OneToMany(mappedBy = "instructor")
    private List<Course> courses = new ArrayList<>();
}

양방향 관계 매핑 설정

관계의 주인 (Owner)

@Entity
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long courseNo;
    
    private String name;
    private String description;
    
    // 관계의 주인: 외래키 소유
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "instructor_no")
    private Instructor instructor;
    
    // getter, setter
    public Instructor getInstructor() {
        return instructor;
    }
    
    public void setInstructor(Instructor instructor) {
        this.instructor = instructor;
    }
}

관계의 주인이 아닌 쪽

@Entity
public class Instructor {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long instructorNo;
    
    private String name;
    private String email;
    
    // 관계의 주인이 아님: mappedBy 사용
    @OneToMany(mappedBy = "instructor")
    private List<Course> courses = new ArrayList<>();
    
    // getter, setter
    public List<Course> getCourses() {
        return courses;
    }
    
    public void setCourses(List<Course> courses) {
        this.courses = courses;
    }
}

매핑 설정 핵심 포인트

관계의 주인

  • • 외래키를 소유
  • • @JoinColumn 사용
  • • 데이터베이스에 반영됨
  • • 관계 변경 권한

관계의 주인이 아닌 쪽

  • • mappedBy 사용
  • • 읽기 전용
  • • 데이터베이스에 반영 안됨
  • • 관계 변경 불가

관계의 주인 (Owner) 개념

왜 관계의 주인이 필요한가?

양방향 관계에서 양쪽 엔티티가 모두 관계를 변경할 수 있다면, 데이터 일관성 문제가 발생할 수 있습니다.

해결책: 한쪽만 관계의 주인으로 지정하여 데이터 변경 권한을 제한

관계의 주인 결정 기준

// 외래키를 가진 쪽이 관계의 주인
@Entity
public class Course {
    // Course 테이블에 instructor_no 컬럼이 있음
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "instructor_no")  // 외래키 소유
    private Instructor instructor;       // 관계의 주인!
}

@Entity
public class Instructor {
    // Instructor 테이블에는 course_no 컬럼이 없음
    @OneToMany(mappedBy = "instructor")  // mappedBy 사용
    private List<Course> courses;        // 관계의 주인이 아님
}

실제 데이터베이스

-- Course 테이블
CREATE TABLE course (
    course_no BIGINT PRIMARY KEY,
    name VARCHAR(255),
    description TEXT,
    instructor_no BIGINT,  -- 외래키
    FOREIGN KEY (instructor_no) REFERENCES instructor(instructor_no)
);

-- Instructor 테이블
CREATE TABLE instructor (
    instructor_no BIGINT PRIMARY KEY,
    name VARCHAR(255),
    email VARCHAR(255)
    -- course_no 컬럼 없음
);

관계의 주인 규칙

  • • 외래키 소유: 실제 외래키를 가진 쪽이 관계의 주인
  • • @JoinColumn: 관계의 주인은 @JoinColumn 사용
  • • mappedBy: 관계의 주인이 아닌 쪽은 mappedBy 사용
  • • 데이터 변경: 관계의 주인만 데이터베이스에 반영
  • • 일관성: 양쪽 엔티티의 컬렉션은 자동으로 동기화

양방향 관계의 문제점

동기화 문제

문제 상황

// 잘못된 사용법
Course course = new Course();
course.setName("JPA 강의");

Instructor instructor = new Instructor();
instructor.setName("김강사");

// 한쪽만 설정 (동기화 안됨)
course.setInstructor(instructor);

// instructor.getCourses()에는 course가 없음!
System.out.println(instructor.getCourses().size()); // 0

// 또는
instructor.getCourses().add(course);
// course.getInstructor()는 null!
System.out.println(course.getInstructor()); // null

실수 가능성

자주 발생하는 실수

  • • 한쪽만 관계 설정
  • • 순서를 바꿔서 설정
  • • null 체크를 깜빡
  • • 관계의 주인을 잘못 설정
  • • 컬렉션 초기화를 깜빡

문제점 정리

동기화 문제

  • • 양쪽 컬렉션 불일치
  • • 데이터 일관성 문제
  • • 예상치 못한 결과

실수 가능성

  • • 복잡한 설정 과정
  • • 순서 의존성
  • • null 체크 필요

코드 복잡성

  • • 반복적인 코드
  • • 유지보수 어려움
  • • 가독성 저하

편의 메서드의 필요성

양방향 관계의 문제점을 해결하기 위해 편의 메서드가 필요합니다.

  • • 동기화 자동화: 양쪽 컬렉션을 자동으로 동기화
  • • 실수 방지: 복잡한 설정 과정을 메서드로 추상화
  • • 코드 간소화: 반복적인 코드를 줄임
  • • 일관성 보장: 항상 올바른 방식으로 관계 설정
  • • 유지보수성: 로직 변경 시 한 곳만 수정
