단방향이란? @ManyToOne @OneToMany 왜 간단한가? 한계점

단방향 관계란?

정의

단방향 관계는 한 엔티티에서 다른 엔티티로의 참조만 존재하고, 반대 방향의 참조는 없는 관계입니다.

핵심: 한쪽에서만 다른 쪽을 참조할 수 있음

단방향 관계 예시

// Course → Instructor (단방향)
@Entity
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long courseNo;
    
    private String name;
    private String description;
    
    // 단방향 관계: Course에서 Instructor만 참조
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "instructor_no")
    private Instructor instructor;
}

@Entity
public class Instructor {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long instructorNo;
    
    private String name;
    private String email;
    
    // Instructor에서는 Course를 참조하지 않음
    // (단방향이므로)
}

관계 방향

Course
↓
@ManyToOne
↓
Instructor

• Course → Instructor: 가능

• Instructor → Course: 불가능

@ManyToOne 관계

기본 설정

@Entity
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long courseNo;
    
    private String name;
    private String description;
    
    // @ManyToOne: 다대일 관계
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "instructor_no")
    private Instructor instructor;
    
    // getter, setter
    public Instructor getInstructor() {
        return instructor;
    }
    
    public void setInstructor(Instructor instructor) {
        this.instructor = instructor;
    }
}

사용법

// 단순한 사용법
Course course = new Course();
course.setName("JPA 강의");
course.setDescription("JPA 기초 강의");

Instructor instructor = instructorRepository.findById(1L);
course.setInstructor(instructor);

courseRepository.save(course);

// 조회 시
Course savedCourse = courseRepository.findById(course.getCourseNo());
Instructor courseInstructor = savedCourse.getInstructor(); // LAZY 로딩

@ManyToOne 특징

외래키 소유

Course 테이블에 instructor_no 컬럼 생성

지연 로딩

FetchType.LAZY가 기본값

@OneToMany 관계

기본 설정

@Entity
public class Instructor {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long instructorNo;
    
    private String name;
    private String email;
    
    // @OneToMany: 일대다 관계 (단방향)
    @OneToMany(fetch = FetchType.LAZY)
    @JoinColumn(name = "instructor_no")
    private List<Course> courses = new ArrayList<>();
    
    // getter, setter
    public List<Course> getCourses() {
        return courses;
    }
    
    public void setCourses(List<Course> courses) {
        this.courses = courses;
    }
}

// 단순한 사용법
Instructor instructor = new Instructor();

// 조회 시

List<Course> instructorCourses = savedInstructor.getCourses(); // LAZY 로딩

@OneToMany 특징

조인 테이블

List, Set 등 컬렉션 사용

단순함

편의 메서드 불필요

왜 단방향은 간단한가?

장점

  • • 단순한 설정: 한 방향만 설정하면 됨
  • • 직관적: 코드만 봐도 관계가 명확
  • • 편의 메서드 불필요: 기본 getter/setter만으로 충분
  • • 성능 좋음: 불필요한 조인 없음
  • • 유지보수 쉬움: 변경할 부분이 적음

단순한 사용 예시

// @ManyToOne 사용
Course course = courseRepository.findById(1L);
Instructor instructor = course.getInstructor(); // 단순한 getter

// @OneToMany 사용  
Instructor instructor = instructorRepository.findById(1L);
List<Course> courses = instructor.getCourses(); // 단순한 getter

// 강의 추가 (단순한 컬렉션 조작)
Course newCourse = new Course();
newCourse.setName("새 강의");
instructor.getCourses().add(newCourse);

// 강의 제거 (단순한 컬렉션 조작)
instructor.getCourses().remove(course);

편의 메서드가 불필요한 이유

  • • 단방향이므로: 한쪽에서만 다른 쪽을 참조
  • • 동기화 불필요: 반대 방향 참조가 없음
  • • 실수 가능성 낮음: 한 곳에서만 관리
  • • 기본 메서드로 충분: getter/setter만으로도 사용 가능

단방향의 한계점

문제 상황

반대 방향 접근 불가

// Instructor에서 자신의 강의 목록을 보고 싶다면?
Instructor instructor = instructorRepository.findById(1L);

// 단방향이므로 직접 접근 불가
// List<Course> courses = instructor.getCourses(); // 불가능!

// 해결 방법: 별도 쿼리 필요
@Query("SELECT c FROM Course c WHERE c.instructor = :instructor")
List<Course> findByInstructor(@Param("instructor") Instructor instructor);

List<Course> courses = courseRepository.findByInstructor(instructor);

성능 문제

N+1 문제 발생

// 모든 강의의 강사 정보를 조회하려면?
List<Course> courses = courseRepository.findAll();

for (Course course : courses) {
    // 각 강의마다 별도 쿼리 실행 (N+1 문제)
    System.out.println(course.getInstructor().getName());
}

// 해결 방법: Fetch Join 필요
@Query("SELECT c FROM Course c JOIN FETCH c.instructor")
List<Course> findAllWithInstructor();

단방향의 한계점 정리

접근성 문제

  • • 반대 방향으로 접근 불가
  • • 별도 쿼리 메서드 필요
  • • 코드 복잡성 증가

성능 문제

  • • N+1 문제 발생 가능
  • • 불필요한 쿼리 실행
  • • Fetch Join 필요

양방향 관계의 필요성

단방향의 한계점을 해결하기 위해 양방향 관계를 사용하게 됩니다.

  • • 양방향 접근: 양쪽에서 서로를 참조 가능
  • • 편의성 향상: 더 직관적인 코드 작성
  • • 성능 최적화: Fetch Join 등 활용 가능
  • • 편의 메서드 필요: 동기화를 위한 편의 메서드 구현
