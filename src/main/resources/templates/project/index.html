⚠️ Step 1에서 개선이 필요한 항목

1. 강의 삭제 (Course DELETE)

현재 상태: 삭제 시도 시 403 Forbidden 에러 발생

원인: Course를 삭제하면 연결된 Week, Session, Enrollment가 고아(orphan) 데이터가 됨. Cascade.REMOVE 없이는 안전한 삭제 불가능

2. 댓글 조회/작성 (Board Comments)

현재 상태: API 미구현

원인: Board → Comment 조회를 위해서는 @OneToMany 양방향 관계 필요. 단방향만으로는 "특정 게시글의 댓글 목록"을 효율적으로 조회할 수 없음

3. 커리큘럼 조회 (Course Curriculum)

현재 상태: API 미구현

원인: Course → Week → Session 계층 구조 조회를 위해 양방향 관계와 편의 메소드 필요. Fetch Join만으로는 복잡한 계층 구조 관리 어려움

4. 수강생 목록 조회 (Course Students)

현재 상태: API 미구현

원인: Course → Enrollment → Student 조회를 위해 Course에 @OneToMany List<Enrollment> 필요. 현재는 Enrollment → Course 단방향만 존재

🚀 Step 2에서 구현 예정 항목

1. 양방향 관계 적용

Board ↔ Comment: @OneToMany 양방향으로 댓글 목록 조회 가능

Course ↔ Week ↔ Session: 양방향으로 커리큘럼 계층 구조 관리

Course ↔ Enrollment: 양방향으로 수강생 목록 조회 가능

2. 편의 메소드 (Convenience Methods)

목적: 양방향 관계의 양쪽을 모두 설정하는 메소드

예: board.addComment(comment) - Board와 Comment 양쪽 참조 자동 설정

3. Cascade 적용

Course 삭제: CascadeType.REMOVE로 Week, Session 자동 삭제

Board 삭제: CascadeType.REMOVE로 Comment 자동 삭제

영속성 전이: CascadeType.PERSIST로 부모 저장 시 자식도 자동 저장

4. 고아 객체 제거 (Orphan Removal)

orphanRemoval = true: 부모 엔티티에서 컬렉션에서 제거된 자식 엔티티를 DB에서도 자동 삭제

5. 새로운 API 엔드포인트

GET /api/boards/{boardNo}/comments - 댓글 목록

POST /api/boards/{boardNo}/comments - 댓글 작성

GET /api/courses/{courseNo}/curriculum - 커리큘럼 조회

GET /api/courses/{courseNo}/students - 수강생 목록

DELETE /api/courses/{courseNo} - 안전한 강의 삭제
