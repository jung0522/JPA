📊 로깅 전략

🔧 Development vs Production 로깅 전략

🛠️ Development 환경

✅ 포함해야 할 로깅

  • SQL 쿼리 로깅: P6Spy, Hibernate SQL 로깅
  • 쿼리 실행 시간: 성능 분석용
  • 파라미터 바인딩: 디버깅용
  • 상세한 에러 스택: 문제 해결용
  • 비즈니스 로직 로깅: 개발 과정 추적
  • HTTP 요청/응답: API 디버깅

⚙️ 설정 예시

# application-dev.properties
logging.level.org.hibernate.SQL=DEBUG
logging.level.org.hibernate.type.descriptor.sql.BasicBinder=TRACE
logging.level.io.goorm.jpa=DEBUG
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

🚀 Production 환경

✅ 포함해야 할 로깅

  • 접근 로깅: 사용자 활동 추적
  • 에러 로깅: 예외 발생 현황
  • 보안 로깅: 인증 실패, 권한 위반
  • 비즈니스 메트릭: 수강신청, 강의 생성 등
  • 성능 로깅: 응답 시간, 처리량
  • 시스템 상태: 메모리, CPU 사용률

⚙️ 설정 예시

# application-prod.properties
logging.level.org.hibernate.SQL=WARN
logging.level.io.goorm.jpa=INFO
logging.level.org.springframework.security=INFO
logging.pattern.file=%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n
logging.file.name=/var/log/jpa-application.log

📊 로깅 레벨 전략

로깅 레벨 Development Production 사용 목적
ERROR ✅ 활성화 ✅ 활성화 시스템 에러, 예외 상황
WARN ✅ 활성화 ✅ 활성화 경고 상황, 잠재적 문제
INFO ✅ 활성화 ✅ 활성화 비즈니스 로직, 사용자 활동
DEBUG ✅ 활성화 ❌ 비활성화 디버깅 정보, 상세 로직
TRACE ✅ 활성화 ❌ 비활성화 매우 상세한 추적 정보

📝 로깅 카테고리별 전략

🔐 보안 로깅

  • • 인증 실패: 잘못된 로그인 시도
  • • 권한 위반: 접근 권한 없는 리소스 접근
  • • 세션 관리: 로그인/로그아웃 활동
  • • API 호출: 민감한 API 접근

💼 비즈니스 로깅

  • • 수강신청: 신청, 승인, 거절 활동
  • • 강의 관리: 생성, 수정, 삭제 활동
  • • 사용자 활동: 주요 기능 사용 현황
  • • 데이터 변경: 중요한 데이터 수정

⚡ 성능 로깅

  • • 응답 시간: API 응답 시간 측정
  • • 쿼리 성능: 느린 쿼리 감지
  • • 메모리 사용량: JVM 메모리 모니터링
  • • 처리량: TPS, RPS 측정

❌ 에러 로깅

  • • 예외 스택: 상세한 에러 정보
  • • 컨텍스트 정보: 에러 발생 시점의 상태
  • • 사용자 정보: 에러 발생한 사용자
  • • 재현 정보: 에러 재현을 위한 정보

2. 로깅 코드 예시

@Slf4j
@Service
public class EnrollmentService {
    
    // 비즈니스 로깅
    public EnrollmentResponse enroll(EnrollmentCreateRequest request) {
        log.info("수강신청 시작: studentId={}, courseId={}", 
                request.getStudentId(), request.getCourseId());
        
        try {
            // 비즈니스 로직
            EnrollmentResponse response = processEnrollment(request);
            
            log.info("수강신청 완료: enrollmentId={}, status={}", 
                    response.getEnrollmentNo(), response.getStatus());
            return response;
            
        } catch (BusinessException e) {
            log.warn("수강신청 실패: studentId={}, courseId={}, reason={}", 
                    request.getStudentId(), request.getCourseId(), e.getMessage());
            throw e;
        } catch (Exception e) {
            log.error("수강신청 중 예상치 못한 오류: studentId={}, courseId={}", 
                    request.getStudentId(), request.getCourseId(), e);
            throw new BusinessException(ErrorCode.INTERNAL_SERVER_ERROR);
        }
    }
    
    // 보안 로깅
    public void checkPermission(Long userId, String action) {
        if (!hasPermission(userId, action)) {
            log.warn("권한 위반: userId={}, action={}, ip={}", 
                    userId, action, getCurrentUserIP());
            throw new BusinessException(ErrorCode.USER_FORBIDDEN);
        }
    }
    
    // 성능 로깅
    public List getMyEnrollments(Pageable pageable) {
        long startTime = System.currentTimeMillis();
        
        try {
            List result = enrollmentRepository.findMyEnrollments(pageable);
            
            long duration = System.currentTimeMillis() - startTime;
            log.info("수강신청 목록 조회 완료: count={}, duration={}ms", 
                    result.size(), duration);
            
            return result;
        } catch (Exception e) {
            long duration = System.currentTimeMillis() - startTime;
            log.error("수강신청 목록 조회 실패: duration={}ms", duration, e);
            throw e;
        }
    }
}

⭐ 로깅 모범 사례

✅ 해야 할 것

  • ✓ 구조화된 로깅: JSON 형태로 로그 출력
  • ✓ 컨텍스트 정보: 사용자 ID, 요청 ID 포함
  • ✓ 적절한 레벨: 상황에 맞는 로깅 레벨 사용
  • ✓ 성능 고려: 로깅이 성능에 미치는 영향 고려
  • ✓ 민감 정보 보호: 패스워드, 토큰 등 로깅 금지

❌ 하지 말아야 할 것

  • ✗ 과도한 로깅: 불필요한 정보까지 로깅
  • ✗ 하드코딩: 로그 메시지 하드코딩
  • ✗ 예외 무시: 로깅 실패 시 예외 무시
  • ✗ 동기 로깅: 성능에 영향을 주는 동기 로깅
  • ✗ 개인정보 노출: 개인정보가 포함된 로그

🎯 핵심 포인트

  • • Development: 상세한 디버깅 정보와 SQL 쿼리 로깅
  • • Production: 보안, 비즈니스, 성능 중심의 로깅
  • • 구조화: JSON 형태의 구조화된 로그 출력
  • • 보안: 민감 정보 보호 및 접근 추적
  • • 성능: 로깅이 시스템 성능에 미치는 영향 최소화
