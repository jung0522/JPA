🔐 JWT 인증

SecurityConfig 주요 변경 사항

기본 Spring Security 설정에서 JWT 인증을 추가하기 위해 다음 부분이 추가됩니다: 

@RequiredArgsConstructor
public class SecurityConfig {

    // ✅ JWT 필터 주입
    private final JwtAuthenticationFilter jwtAuthenticationFilter;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(AbstractHttpConfigurer::disable)
            // ✅ Stateless 세션 (JWT 사용 시 필수)
            .sessionManagement(session -> session
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            )
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()  // 로그인/회원가입 허용
                .anyRequest().authenticated()
            )
            // ✅ JWT 필터를 UsernamePasswordAuthenticationFilter 앞에 추가
            .addFilterBefore(jwtAuthenticationFilter,
                             UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }
}

핵심: JWT 필터가 모든 요청을 가로채서 토큰을 검증하고, 인증 정보를 SecurityContext에 저장합니다.

필요한 파일 구조

📦

JwtTokenProvider.java

config/jwt/JwtTokenProvider.java

역할: JWT 토큰 생성, 검증, 파싱을 담당합니다.

  • • generateToken(username) - 토큰 생성
  • • validateToken(token) - 토큰 유효성 검증
  • • getUsernameFromToken(token) - 토큰에서 사용자명 추출
🔍

JwtAuthenticationFilter.java

config/jwt/JwtAuthenticationFilter.java

역할: 모든 요청을 가로채서 JWT 토큰을 검증하고 인증 정보를 설정합니다.

  • • HTTP 요청 헤더에서 Authorization: Bearer {token} 추출
  • • 토큰 유효성 검증 후 SecurityContext에 인증 정보 저장
  • • 이후 모든 컨트롤러에서 @AuthenticationPrincipal로 사용자 정보 접근 가능
⚠️

JwtAuthenticationEntryPoint.java

config/jwt/JwtAuthenticationEntryPoint.java

역할: 인증 실패 시 표준화된 에러 응답을 반환합니다.

  • • 토큰이 없거나 유효하지 않을 때 401 Unauthorized 응답
  • • 일관된 JSON 에러 형식 제공

인증된 사용자로 API 실행, Entity 저장 시 자동으로 생성자 기록

📝 JPA Auditing

JPA Auditing은 Entity의 생성/수정 시간과 생성자/수정자를 자동으로 기록하는 기능입니다. JWT 인증과 결합하여 "누가, 언제" 데이터를 생성/수정했는지 자동 추적합니다.

필요한 파일 구조

⚙️

JpaConfig.java

config/JpaConfig.java

역할: JPA Auditing을 활성화하고 현재 작업자 정보를 제공합니다. 

@Configuration
@EnableJpaAuditing  // ← Auditing 활성화
public class JpaConfig {

    @Bean
    public AuditorAware<String> auditorProvider() {
        return () -> {
            Authentication auth = SecurityContextHolder
                .getContext()
                .getAuthentication();

            // ✅ JWT 필터가 저장한 인증 정보에서 사용자명 추출
            if (auth == null || !auth.isAuthenticated()) {
                return Optional.empty();
            }

            return Optional.of(auth.getName());
        };
    }
}

핵심: SecurityContext에서 JWT로 인증된 사용자 정보를 가져옵니다.

📦

BaseEntity.java

entity/common/BaseEntity.java

역할: 모든 Entity가 상속받는 공통 필드를 정의합니다.

자동 기록되는 필드:

  • • createdAt - 생성 시간 (@CreatedDate)
  • • updatedAt - 수정 시간 (@LastModifiedDate)
  • • createdBy - 생성자 (@CreatedBy) ← JWT 사용자
  • • lastModifiedBy - 수정자 (@LastModifiedBy) ← JWT 사용자

Entity에 적용하는 방법

@Entity
@Table(name = "users")
public class User extends BaseEntity {  // ← BaseEntity 상속

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String username;
    private String email;

    // ... 다른 필드들
}

// 저장 예시
User user = new User();
user.setUsername("student01");
userRepository.save(user);

// ✅ 자동으로 기록됨:
// - createdAt: 2025-10-19 15:30:00
// - createdBy: "admin"  (JWT 토큰의 사용자명)
// - updatedAt: 2025-10-19 15:30:00
// - lastModifiedBy: "admin"

💡 실무 팁

extends BaseEntity만 추가하면 됩니다. 나머지는 JPA Auditing이 자동으로 처리하며, JWT에서 가져온 사용자명이 자동으로 기록됩니다.

자동 기록 확인하기

방법 1: H2 Console에서 확인

SELECT id, username, created_at, created_by,
       updated_at, last_modified_by
FROM users;

방법 2: Swagger UI에서 확인

  1. Swagger UI에서 로그인 (/api/auth/login) → JWT 토큰 복사
  2. 🔓 Authorize 버튼 클릭 → Bearer {token} 입력
  3. POST /api/users로 새 사용자 생성
  4. GET /api/users로 조회 → createdBy 필드 확인

방법 3: 로그 확인

P6Spy가 활성화되어 있어 SQL 로그에서 실제 INSERT 쿼리를 볼 수 있습니다: 

INSERT INTO users (username, email, created_at, created_by,
                   updated_at, last_modified_by)
VALUES ('student01', 'student@example.com',
        '2025-10-19 15:30:00', 'admin',
        '2025-10-19 15:30:00', 'admin');
