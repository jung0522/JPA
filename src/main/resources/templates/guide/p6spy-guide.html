P6Spy SQL 로깅

실제 파라미터가 바인딩된 SQL 쿼리 확인하기

🔍 P6Spy란?

P6Spy는 실제 바인딩된 파라미터 값을 포함한 SQL 쿼리를 로그에 출력하는 라이브러리입니다.

❌ 일반 Hibernate 로그

SELECT * FROM users WHERE username = ?
-- 파라미터 값을 알 수 없음!

✅ P6Spy 로그

SELECT * FROM users WHERE username = 'admin'
-- 실제 값이 보임!

💡 왜 필요한가?

  • • 디버깅 편의성: 쿼리를 그대로 복사해서 H2 Console에 붙여넣기 가능
  • • 성능 분석: 실제 실행되는 쿼리 확인으로 N+1 문제 발견
  • • 학습 도구: JPA가 생성하는 SQL을 정확히 파악

⚙️ 현재 프로젝트 설정

1. build.gradle 의존성

dependencies {
    // P6Spy - SQL 로깅 (실제 파라미터 포함)
    implementation 'com.github.gavlyukovskiy:p6spy-spring-boot-starter:1.9.0'
}

gavlyukovskiy/p6spy-spring-boot-starter는 Spring Boot 자동 설정을 제공하는 간편한 라이브러리입니다.

2. application-jpa.properties 설정

# JPA/Hibernate
spring.jpa.show-sql=false  # ← Hibernate의 기본 로그 비활성화
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.properties.hibernate.use_sql_comments=true

# P6Spy - SQL 로깅 (실제 파라미터 포함)
decorator.datasource.p6spy.enable-logging=true  # ← P6Spy 활성화
decorator.datasource.p6spy.multiline=true       # ← 멀티라인 포맷
decorator.datasource.p6spy.logging=slf4j        # ← SLF4J 로거 사용

주의: show-sql=false로 설정하여 Hibernate의 기본 로그와 중복을 방지합니다. P6Spy가 더 보기 좋은 형태로 출력합니다.

3. 사용 이유

enable-logging=true

P6Spy 로깅 활성화 (필수)

multiline=true

SQL을 여러 줄로 보기 좋게 포맷 (가독성 향상)

logging=slf4j

Spring Boot의 표준 로깅 시스템(SLF4J) 사용

📋 로그 출력 예시

로그인 시 사용자 조회

2025-10-19 15:30:00.123 [http-nio-8080-exec-1] INFO  p6spy -
#1725881400123 | took 5ms | statement | connection 1 | url jdbc:h2:mem:testdb

SELECT
    user0_.user_no AS user_no1_0_,
    user0_.username AS username2_0_,
    user0_.password AS password3_0_,
    user0_.email AS email4_0_,
    user0_.role AS role5_0_
FROM users user0_
WHERE user0_.username = 'admin';
-- 👆 실제 파라미터 'admin'이 그대로 보임!

새 사용자 생성 (Auditing 포함)

INSERT INTO users
    (username, password, email, full_name, role,
     created_at, created_by, updated_at, last_modified_by, deleted)
VALUES
    ('student03', '$2a$10$...encrypted...', 'student03@goorm.io',
     '학생03', 'USER',
     '2025-10-19 15:31:00', 'admin',
     '2025-10-19 15:31:00', 'admin', false);
-- 👆 Auditing으로 자동 입력된 created_by='admin' 확인 가능!

N+1 문제 발견

SELECT * FROM posts;  -- 1번 쿼리
SELECT * FROM comments WHERE post_id = 1;  -- N번 쿼리 (반복!)
SELECT * FROM comments WHERE post_id = 2;
SELECT * FROM comments WHERE post_id = 3;
...
-- ❌ N+1 문제 발견! Fetch Join으로 해결 필요

P6Spy 로그를 보면 예상보다 많은 쿼리가 실행되는 것을 쉽게 발견할 수 있습니다.

🔧 추가로 알아두면 좋은 설정

쿼리 실행 시간 표시

P6Spy는 기본적으로 각 쿼리의 실행 시간을 표시합니다. 

took 5ms | SELECT * FROM users WHERE username = 'admin';
took 150ms | SELECT * FROM posts;  -- ⚠️ 느린 쿼리 발견!

성능 문제가 있는 쿼리를 쉽게 찾을 수 있습니다.

느린 쿼리만 로그에 출력

특정 시간 이상 걸리는 쿼리만 로깅하려면: 

# application-jpa.properties에 추가
decorator.datasource.p6spy.log-slow-queries=true
decorator.datasource.p6spy.slow-query-threshold=100  # 100ms 이상

운영 환경에서는 비활성화

P6Spy는 성능 오버헤드가 있으므로 운영 환경에서는 비활성화하는 것을 권장합니다. 

# application-prod.properties (운영 환경)
decorator.datasource.p6spy.enable-logging=false  # ← 비활성화

# 또는 의존성을 runtimeOnly로 변경
runtimeOnly 'com.github.gavlyukovskiy:p6spy-spring-boot-starter:1.9.0'

커스텀 포맷 (선택)

더 세밀한 제어가 필요하면 spy.properties 파일을 사용할 수 있습니다.

src/main/resources/spy.properties 파일 생성:

dateformat=yyyy-MM-dd HH:mm:ss
logMessageFormat=com.p6spy.engine.spy.appender.CustomLineFormat
customLogMessageFormat=%(currentTime) | took %(executionTime)ms | %(sql)

현재 프로젝트는 기본 설정으로 충분하므로 별도 파일 불필요

🚀 사용 방법

1. 애플리케이션 실행

./gradlew bootRun

2. API 호출

Swagger UI 또는 Postman으로 API를 호출하면 콘솔에 P6Spy 로그가 출력됩니다.

3. 로그 확인

IntelliJ 또는 터미널에서 p6spy 키워드로 검색하면 SQL 로그만 필터링할 수 있습니다.

4. 쿼리 복사 & 테스트

P6Spy 로그에서 SQL을 복사해서 H2 Console에 직접 붙여넣어 테스트할 수 있습니다.
