Actuator 모니터링 가이드

Spring Boot Actuator를 활용한 애플리케이션 모니터링 및 관리

📊 Actuator란?

Spring Boot Actuator는 애플리케이션의 **모니터링 및 관리 기능**을 제공하는 프로덕션 레벨 도구입니다.

💡 핵심 개념: Actuator는 JSON 형식으로 메트릭과 상태 정보를 제공합니다. 브라우저에서 직접 보기보다는 모니터링 도구(Prometheus, Grafana)나 관리 대시보드(Spring Boot Admin)에서 활용합니다.

🎯 주요 엔드포인트

GET

/actuator/health

애플리케이션의 전반적인 상태를 확인합니다.

직접 확인하기 →

응답 예시:

{
  "status": "UP",
  "components": {
    "db": {
      "status": "UP",
      "details": { "database": "H2" }
    },
    "diskSpace": {
      "status": "UP"
    }
  }
}

✅ status: UP → 정상 동작 중

❌ status: DOWN → 문제 발생 (DB 연결 끊김, 디스크 부족 등)

GET

/actuator/metrics

측정 가능한 모든 메트릭의 목록을 반환합니다.

직접 확인하기 →
GET

/actuator/metrics/{메트릭명}

특정 메트릭의 상세 정보를 확인합니다.

메모리 사용량 → HTTP 요청 통계 →

🎓 실무 활용 시나리오

1️⃣ "API가 갑자기 느려졌어요!"

확인 방법: /actuator/metrics/http.server.requests

  • • COUNT: 요청이 몇 번 왔는지
  • • TOTAL_TIME: 총 소요 시간
  • • MAX: 가장 느린 요청 시간
  • • 평균 응답시간 = TOTAL_TIME / COUNT

2️⃣ "메모리가 계속 증가해요!"

확인 방법: /actuator/metrics/jvm.memory.used

  • • 주기적으로 확인해서 계속 증가하면 → 메모리 누수 의심
  • • GC 후에도 줄어들지 않으면 → 큰 객체가 계속 생성되고 있음

3️⃣ "DB 연결이 안 돼요!"

확인 방법: /actuator/health

  • • db.status: DOWN → DB 연결 문제
  • • hikaricp.connections.active가 최대치 → 커넥션 풀 부족

4️⃣ "JPA N+1 문제 있나요?"

확인 방법: 로그 + HTTP 요청 시간 비교

  • • P6Spy 로그로 쿼리 개수 확인
  • • http.server.requests로 응답 시간 확인
  • • 쿼리가 많으면서 응답 시간이 길면 → N+1 문제

🔒 운영 환경 보안 설정

⚠️ 주의: 현재 설정은 개발 환경용입니다!

운영 환경에서는 Actuator 엔드포인트를 모두에게 공개하면 안 됩니다. 시스템 정보 유출 및 보안 위협이 발생할 수 있습니다.

운영 환경 권장 설정

1. 필요한 엔드포인트만 노출

application.properties 수정:

# 개발 환경 (현재)
management.endpoints.web.exposure.include=health,info,metrics

# 운영 환경 (권장)
management.endpoints.web.exposure.include=health,info
management.endpoint.health.show-details=when-authorized

2. 인증 추가

SecurityConfig.java 수정:

// 개발 환경 (현재)
.requestMatchers("/actuator/**").permitAll()

// 운영 환경 (권장)
.requestMatchers("/actuator/health").permitAll()  // health만 공개
.requestMatchers("/actuator/**").hasRole("ADMIN")  // 나머지는 ADMIN만

3. 기본 경로 변경

예측 가능한 /actuator 경로를 변경:

# application.properties
management.endpoints.web.base-path=/internal-monitoring

→ 접근 경로: /internal-monitoring/health

4. 네트워크 제한

방화벽 또는 인프라 레벨에서 접근 제한:

  • • VPN을 통해서만 접근 허용
  • • 특정 IP 대역만 허용 (관리자 네트워크)
  • • Kubernetes: NetworkPolicy로 제한

5. 별도 포트 사용

Actuator를 별도 포트로 분리:

# application.properties
server.port=8080
management.server.port=9090  # Actuator 전용 포트

→ 일반 사용자는 8080만, 관리자는 9090도 접근 가능하도록 설정
