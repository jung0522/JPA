데이터 초기화

CommandLineRunner를 이용한 테스트 데이터 자동 생성

🌱 JpaDataInitializer 역할

JpaDataInitializer는 애플리케이션 시작 시 자동으로 테스트 데이터를 생성하는 컴포넌트입니다.

✅ 현재 동작

  • • CommandLineRunner 인터페이스 구현으로 애플리케이션 시작 후 자동 실행
  • • @Profile("jpa")로 특정 프로파일에서만 실행 (운영 환경 제외 가능)
  • • Admin 1명, 일반 사용자 2명 자동 생성
  • • SecurityContext 설정으로 Auditing도 함께 작동

📍 파일 위치

config/JpaDataInitializer.java

🔧 활성화 조건

spring.profiles.active=jpa

⚙️ CommandLineRunner란?

Spring Boot에서 애플리케이션이 시작된 직후에 특정 코드를 실행하고 싶을 때 사용하는 인터페이스입니다. 

@Component
@Profile("jpa")  // ← jpa 프로파일에서만 실행
public class JpaDataInitializer implements CommandLineRunner {

    @Override
    @Transactional
    public void run(String... args) {
        // ✅ 애플리케이션 시작 후 자동 실행되는 코드
        // 테스트 데이터 생성 로직
    }
}

✅ 장점

  • • 개발 환경에서 테스트 데이터 자동 생성
  • • 수동 데이터 입력 불필요
  • • 팀원 간 동일한 초기 데이터 공유

⚠️ 주의점

  • • 매번 실행되므로 중복 데이터 방지 필요
  • • 운영 환경에서는 비활성화 권장
  • • 영구 DB 사용 시 추가 로직 필요

💾 인메모리 DB에서의 사용 (현재 H2)

현재 설정 (H2 In-Memory)

현재 프로젝트는 H2 인메모리 데이터베이스를 사용합니다.

  • • ✅ 애플리케이션 재시작 시 데이터베이스가 완전히 초기화
  • • ✅ 중복 데이터 걱정 없음 (매번 빈 DB에서 시작)
  • • ✅ 현재 코드 그대로 사용 가능

현재 application-jpa.properties 설정

spring.datasource.url=jdbc:h2:mem:testdb
spring.jpa.hibernate.ddl-auto=create

# ✅ create: 매번 테이블 drop 후 재생성
#    → JpaDataInitializer가 매번 새로운 데이터 생성

⚠️ 영구 DB 사용 시 추가 고려사항

MySQL, PostgreSQL 같은 영구 데이터베이스를 사용할 때는 중복 데이터 생성을 방지하는 로직이 필요합니다.

🚨 문제 상황

영구 DB에서 ddl-auto=update 또는 validate 사용 시:

  • • ❌ 애플리케이션 재시작할 때마다 동일한 데이터 생성 시도
  • • ❌ Duplicate entry 'admin' for key 'username' 에러 발생
  • • ❌ 애플리케이션 시작 실패

✅ 해결 방법: 간단한 중복 실행 방지

메서드 시작 시 데이터가 이미 존재하면 바로 종료합니다. 

@Override
@Transactional
public void run(String... args) {
    log.info("=== JPA Data Initialization Started ===");

    // ✅ 중복 실행 방지: 데이터가 이미 있으면 종료
    if (userRepository.count() > 0) {
        log.info("=== 데이터가 이미 존재하여 초기화를 건너뜁니다. ===");
        return;
    }

    // Admin 사용자 생성
    User admin = User.builder()
            .username("admin")
            .password(passwordEncoder.encode("1234"))
            .email("admin@goorm.io")
            .fullName("관리자")
            .role(UserRole.ADMIN)
            .build();
    userRepository.save(admin);
    log.info("Admin user created: {}", admin.getUsername());

    // SecurityContext 설정 (Auditing을 위해)
    Authentication authentication = new UsernamePasswordAuthenticationToken(
            admin.getUserNo().toString(),
            null,
            List.of(new SimpleGrantedAuthority("ROLE_ADMIN"))
    );
    SecurityContextHolder.getContext().setAuthentication(authentication);

    // 일반 사용자 생성
    User student01 = User.builder()
            .username("student01")
            .password(passwordEncoder.encode("1234"))
            .email("student01@goorm.io")
            .fullName("학생01")
            .role(UserRole.USER)
            .build();
    userRepository.save(student01);
    log.info("User created: {}", student01.getUsername());

    User student02 = User.builder()
            .username("student02")
            .password(passwordEncoder.encode("1234"))
            .email("student02@goorm.io")
            .fullName("학생02")
            .role(UserRole.USER)
            .build();
    userRepository.save(student02);
    log.info("User created: {}", student02.getUsername());

    log.info("=== JPA Data Initialization Completed ===");
}

💡 간단하고 실용적!

  • • count() > 0 한 번만 체크
  • • 개별 필드 체크 불필요
  • • 코드 간결, 유지보수 쉬움

📋 영구 DB 설정 예시 (MySQL)

# application-prod.properties (운영 환경)
spring.datasource.url=jdbc:mysql://localhost:3306/mydb
spring.datasource.username=root
spring.datasource.password=password
spring.jpa.hibernate.ddl-auto=validate  # ← 기존 테이블 유지

# ✅ validate: 테이블 구조만 검증, 데이터 유지
#    → existsByUsername() 체크 필수!

🚀 운영 환경에서 비활성화하기

운영 환경에서는 테스트 데이터 생성이 불필요하므로 @Profile로 제어합니다.

✅ 현재 설정 (이미 적용됨)

@Component
@Profile("jpa")  // ← "jpa" 프로파일에서만 실행
public class JpaDataInitializer implements CommandLineRunner {
    // ...
}

spring.profiles.active=jpa일 때만 실행됩니다.

개발 환경 (application-jpa.properties)

# 실행됨 ✅
spring.profiles.active=jpa

→ JpaDataInitializer 실행, 테스트 데이터 생성

운영 환경 (application-prod.properties)

# 실행 안 됨 ❌
spring.profiles.active=prod

→ JpaDataInitializer 실행 안 됨, 기존 데이터 유지

➕ 테스트 데이터 추가하는 방법

새로운 엔티티(예: Board, Course)를 추가할 때 초기 데이터도 함께 생성하고 싶다면:

1. Repository 주입

@RequiredArgsConstructor
public class JpaDataInitializer implements CommandLineRunner {

    private final UserRepository userRepository;
    private final BoardRepository boardRepository;  // ← 추가
    private final PasswordEncoder passwordEncoder;
}

2. run() 메서드에 생성 로직 추가

@Override
@Transactional
public void run(String... args) {
    // ... 기존 User 생성 로직 ...

    // ✅ Board 데이터 추가
    if (!boardRepository.existsByTitle("공지사항")) {
        Board board = Board.builder()
                .title("공지사항")
                .content("환영합니다!")
                .author(admin)
                .build();
        boardRepository.save(board);
        log.info("Board created: {}", board.getTitle());
    }
}

3. 애플리케이션 재시작

H2 인메모리 DB 사용 중이므로 재시작하면 자동으로 새 데이터가 생성됩니다.

💡 실무 팁

  • • 대량의 테스트 데이터가 필요하면 반복문 사용 (예: 100개의 게시글 생성)
  • • 외래 키 관계가 있다면 먼저 부모 엔티티를 생성 후 자식 생성
  • • 영구 DB 사용 시 반드시 existsBy...() 체크
