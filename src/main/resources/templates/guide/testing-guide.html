Repository 테스트 (@DataJpaTest)

CourseRepositoryTest 예시

@DataJpaTest
class CourseRepositoryTest {

    @Autowired
    private TestEntityManager entityManager;

    @Autowired
    private CourseRepository courseRepository;

    @Test
    @DisplayName("강의 ID로 조회 - 성공")
    void findById_성공() {
        // given
        Course course = Course.builder()
                .name("테스트 강의")
                .build();
        entityManager.persistAndFlush(course);

        // when
        Optional<Course> found = courseRepository.findById(course.getCourseNo());

        // then
        assertThat(found).isPresent();
        assertThat(found.get().getName()).isEqualTo("테스트 강의");
    }
}

💡 Repository 테스트 핵심 포인트

  • • @DataJpaTest: JPA 관련 컴포넌트만 로드
  • • TestEntityManager: 테스트용 엔티티 관리
  • • Given-When-Then 패턴으로 테스트 구조화
  • • @DisplayName으로 테스트 의도 명확화

Service 테스트 (@ExtendWith)

CourseServiceTest 예시

@ExtendWith(MockitoExtension.class)
class CourseServiceTest {

    @Mock
    private CourseRepository courseRepository;

    @InjectMocks
    private CourseService courseService;

    @Test
    @DisplayName("강의 생성 - 성공")
    void createCourse_성공() {
        // given
        CourseCreateRequest request = CourseCreateRequest.builder()
                .name("새로운 강의")
                .build();

        given(courseRepository.save(any(Course.class)))
                .willReturn(course);

        // when
        CourseResponse response = courseService.create(request);

        // then
        assertThat(response.getName()).isEqualTo("테스트 강의");
        verify(courseRepository).save(any(Course.class));
    }
}

💡 Service 테스트 핵심 포인트

  • • @Mock: 의존성 모킹
  • • @InjectMocks: 테스트 대상에 모킹된 의존성 주입
  • • given().willReturn(): 모킹된 메서드의 반환값 설정
  • • verify(): 메서드 호출 검증

Controller 테스트 (@WebMvcTest)

CourseApiControllerTest 예시

@WebMvcTest(CourseApiController.class)
class CourseApiControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean
    private CourseService courseService;

    @Test
    @DisplayName("강의 생성 API - 성공")
    void createCourse_성공() throws Exception {
        // given
        CourseCreateRequest request = CourseCreateRequest.builder()
                .name("새로운 강의")
                .build();

        given(courseService.create(any())).willReturn(courseResponse);

        // when & then
        mockMvc.perform(post("/api/courses")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content(objectMapper.writeValueAsString(request)))
                .andExpect(status().isCreated())
                .andExpect(jsonPath("$.success").value(true));
    }
}

💡 Controller 테스트 핵심 포인트

  • • @WebMvcTest: MVC 관련 컴포넌트만 로드
  • • MockMvc: HTTP 요청/응답 시뮬레이션
  • • @MockBean: Spring 컨텍스트의 빈 모킹
  • • jsonPath(): JSON 응답 검증

통합 테스트 (@SpringBootTest)

EnrollmentIntegrationTest 예시

@SpringBootTest
@ActiveProfiles("test")
@Transactional
class EnrollmentIntegrationTest {

    @Autowired
    private EnrollmentService enrollmentService;

    @Test
    @DisplayName("수강신청 전체 플로우 - 성공")
    void enrollmentFullFlow_성공() {
        // given
        EnrollmentCreateRequest request = EnrollmentCreateRequest.builder()
                .courseNo(course.getCourseNo())
                .build();

        // when - 수강신청
        EnrollmentResponse response = enrollmentService.enroll(request, student);

        // then - 수강신청 확인
        assertThat(response.getStatus()).isEqualTo(EnrollmentStatus.PENDING);

        // when - 수강신청 승인
        EnrollmentResponse approved = enrollmentService.approve(response.getEnrollmentNo());

테스트 작성 팁

✅ 좋은 테스트

  • • 명확한 이름: 테스트 의도가 명확한 메서드명
  • • 단일 책임: 하나의 테스트는 하나의 기능만
  • • 독립성: 다른 테스트에 의존하지 않음
  • • 반복 가능: 언제 실행해도 같은 결과
  • • 빠른 실행: 빠르게 실행되어 자주 테스트 가능

❌ 나쁜 테스트

  • • 불명확한 이름: test1, testMethod 등
  • • 여러 기능: 하나의 테스트에서 여러 기능 검증
  • • 의존성: 다른 테스트의 결과에 의존
  • • 불안정: 실행할 때마다 결과가 다름
  • • 느린 실행: 실행 시간이 오래 걸림

📝 Given-When-Then 패턴

Given: 테스트에 필요한 데이터 준비

When: 테스트할 기능 실행

Then: 결과 검증
