# QueryDSL 기본

## 이론

### QueryDSL이란?
- **정의**: 타입 안전한 쿼리를 위한 오픈소스 프레임워크
- **특징**: 컴파일 타임에 쿼리 오류 발견
- **장점**: JPQL의 가독성 + Criteria의 동적 쿼리 능력
- **핵심**: Q클래스 (Query Type)를 사용한 타입 안전 쿼리

### JPQL vs Criteria vs QueryDSL

```java
// JPQL - 가독성 좋지만 동적 쿼리 불가
@Query("SELECT c FROM Comment c WHERE c.content LIKE %:keyword%")

// Criteria - 동적 쿼리 가능하지만 가독성 나쁨
cb.like(root.get("content"), "%" + keyword + "%")  // 문자열 "content" 여전히 오타 위험

// QueryDSL - 둘 다 해결! 🎉
comment.content.contains(keyword)  // 타입 안전 + 가독성
```

@Repository

    public List<Comment> findAll() {

### 3. 동적 쿼리 (BooleanBuilder)

```java
@Override
public List<Comment> searchComments(CommentSearchCondition condition) {
    QComment comment = QComment.comment;

    BooleanBuilder builder = new BooleanBuilder();

    // 키워드가 있으면 추가
    if (condition.getKeyword() != null) {
        builder.and(comment.content.contains(condition.getKeyword()));
    }

    // postId가 있으면 추가
    if (condition.getPostId() != null) {
        builder.and(comment.post.id.eq(condition.getPostId()));
    }

    // 작성일 범위
    if (condition.getStartDate() != null) {
        builder.and(comment.createdAt.goe(condition.getStartDate()));
    }
    if (condition.getEndDate() != null) {
        builder.and(comment.createdAt.loe(condition.getEndDate()));
    }

    return queryFactory
        .selectFrom(comment)
        .where(builder)
        .orderBy(comment.id.desc())
        .fetch();
}
```

### 5. 프로젝션 (DTO)

**방법 1: Projections.bean (Setter 사용)**
```java
@Getter @Setter
public class CommentDto {
    private Long id;
    private String content;
    private String postTitle;
}

public List<CommentDto> findCommentsDto() {
    QComment comment = QComment.comment;
    QPost post = QPost.post;

    return queryFactory
        .select(Projections.bean(CommentDto.class,
            comment.id,
            comment.content,
            post.title.as("postTitle")
        ))
        .from(comment)
        .join(comment.post, post)
        .fetch();
}
```

**방법 2: Projections.fields (필드 직접 주입)**
```java
return queryFactory
    .select(Projections.fields(CommentDto.class,
        comment.id,
        comment.content,
        post.title.as("postTitle")
    ))
    .from(comment)
    .join(comment.post, post)
    .fetch();
```

**방법 3: Projections.constructor (생성자)**
```java
@Getter
public class CommentDto {
    private Long id;
    private String content;
    private String postTitle;

    public CommentDto(Long id, String content, String postTitle) {
        this.id = id;
        this.content = content;
        this.postTitle = postTitle;
    }
}

return queryFactory
    .select(Projections.constructor(CommentDto.class,
        comment.id,
        comment.content,
        post.title
    ))
    .from(comment)
    .join(comment.post, post)
    .fetch();
```

**방법 4: @QueryProjection (권장!)**
```java
@Getter
public class CommentDto {
    private Long id;
    private String content;
    private String postTitle;

    @QueryProjection  // Q클래스 생성!
    public CommentDto(Long id, String content, String postTitle) {
        this.id = id;
        this.content = content;
        this.postTitle = postTitle;
    }
}

// 빌드 후 QCommentDto 생성됨
return queryFactory
    .select(new QCommentDto(
        comment.id,
        comment.content,
        post.title
    ))
    .from(comment)
    .join(comment.post, post)
    .fetch();
```

### 6. 집계 쿼리

```java
// COUNT
public Long countByPostId(Long postId) {
    QComment comment = QComment.comment;

    return queryFactory
        .select(comment.count())
        .from(comment)
        .where(comment.post.id.eq(postId))
        .fetchOne();
}

// GROUP BY
public List<CommentStatDto> countByPost() {
    QComment comment = QComment.comment;
    QPost post = QPost.post;

    return queryFactory
        .select(new QCommentStatDto(
            post.id,
            post.title,
            comment.count()
        ))
        .from(comment)
        .join(comment.post, post)
        .groupBy(post.id, post.title)
        .fetch();
}

// HAVING
public List<CommentStatDto> findPopularPosts(Long minCount) {
    QComment comment = QComment.comment;
    QPost post = QPost.post;

    return queryFactory
        .select(new QCommentStatDto(
            post.id,
            post.title,
            comment.count()
        ))
        .from(comment)
        .join(comment.post, post)
        .groupBy(post.id, post.title)
        .having(comment.count().goe(minCount))
        .orderBy(comment.count().desc())
        .fetch();
}
```

### 7. 페이징

```java
public Page<Comment> findCommentsWithPaging(Pageable pageable) {
    QComment comment = QComment.comment;

    // 데이터 조회
    List<Comment> content = queryFactory
        .selectFrom(comment)
        .offset(pageable.getOffset())
        .limit(pageable.getPageSize())
        .orderBy(comment.id.desc())
        .fetch();

    // 전체 개수 조회
    Long total = queryFactory
        .select(comment.count())
        .from(comment)
        .fetchOne();

    return new PageImpl<>(content, pageable, total);
}

// 최적화: fetchResults() 대신 별도 쿼리 (권장)
public Page<Comment> findCommentsWithPagingOptimized(Pageable pageable) {
    QComment comment = QComment.comment;

    // 1. 데이터 조회
    List<Comment> content = queryFactory
        .selectFrom(comment)
        .offset(pageable.getOffset())
        .limit(pageable.getPageSize())
        .orderBy(comment.id.desc())
        .fetch();

    // 2. 카운트 쿼리 (조건이 복잡하면 최적화 가능)
    JPAQuery<Long> countQuery = queryFactory
        .select(comment.count())
        .from(comment);

    return PageableExecutionUtils.getPage(content, pageable, countQuery::fetchOne);
}
```

## QueryDSL 조건 메서드

### 비교 연산자
```java
comment.id.eq(1L)           // id = 1
comment.id.ne(1L)           // id != 1
comment.id.goe(1L)          // id >= 1 (greater or equal)
comment.id.gt(1L)           // id > 1 (greater than)
comment.id.loe(1L)          // id <= 1 (less or equal)
comment.id.lt(1L)           // id < 1 (less than)
```

### 문자열 검색
```java
comment.content.contains("키워드")       // LIKE '%키워드%'
comment.content.startsWith("키워드")    // LIKE '키워드%'
comment.content.endsWith("키워드")      // LIKE '%키워드'
comment.content.like("%키워드%")        // LIKE '%키워드%'
```

### NULL 체크
```java
comment.content.isNull()
comment.content.isNotNull()
```

### IN 절
```java
comment.id.in(1L, 2L, 3L)
comment.id.notIn(1L, 2L, 3L)
```

### BETWEEN
```java
comment.id.between(1L, 10L)
comment.createdAt.between(startDate, endDate)
```

## API 엔드포인트

```java
@RestController
@RequestMapping("/api/querydsl/comments")
@RequiredArgsConstructor
public class CommentQueryController {

    private final CommentQueryService service;

    // 동적 검색
    @GetMapping("/search")
    public ResponseEntity<List<CommentDto>> search(
        @RequestParam(required = false) String keyword,
        @RequestParam(required = false) Long postId,
        @RequestParam(required = false) @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate startDate,
        @RequestParam(required = false) @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate endDate
    ) {
        CommentSearchCondition condition = new CommentSearchCondition();
        condition.setKeyword(keyword);
        condition.setPostId(postId);
        if (startDate != null) condition.setStartDate(startDate.atStartOfDay());
        if (endDate != null) condition.setEndDate(endDate.atTime(23, 59, 59));

        return ResponseEntity.ok(service.searchComments(condition));
    }

    // 페이징
    @GetMapping
    public ResponseEntity<Page<CommentDto>> getComments(Pageable pageable) {
        return ResponseEntity.ok(service.findCommentsWithPaging(pageable));
    }

    // 통계
    @GetMapping("/stats/popular")
    public ResponseEntity<List<CommentStatDto>> getPopularPosts(
        @RequestParam(defaultValue = "5") Long minCount
    ) {
        return ResponseEntity.ok(service.findPopularPosts(minCount));
    }
}
```

## 핵심 정리

### ✅ QueryDSL의 장점

1. **완전한 타입 안정성**
   ```java
   comment.content.contains("키워드")  // ✅ 컴파일 타임 체크
   comment.conten.contains("키워드")   // ❌ 컴파일 에러!
   ```

2. **가독성**
   ```java
   // SQL과 거의 동일!
   queryFactory
       .selectFrom(comment)
       .where(comment.post.id.eq(1L))
       .orderBy(comment.id.desc())
       .fetch();
   ```

3. **동적 쿼리 작성 쉬움**
   ```java
   BooleanBuilder builder = new BooleanBuilder();
   if (keyword != null) builder.and(comment.content.contains(keyword));
   if (postId != null) builder.and(comment.post.id.eq(postId));
   ```

4. **IDE 지원 완벽**
   - 자동완성
   - 리팩터링 (필드명 변경 시 자동 반영)
   - 컴파일 타임 오류 발견

5. **테스트 가능**
   - 메서드 단위로 테스트 작성 가능

### 📊 비교표

| 구분 | JPQL | Criteria | QueryDSL |
|------|------|----------|----------|
| **타입 안정성** | ❌ | △ | ✅ |
| **가독성** | ✅ | ❌ | ✅ |
| **동적 쿼리** | ❌ | ✅ | ✅ |
| **IDE 지원** | ❌ | △ | ✅ |
| **학습 곡선** | 쉬움 | 어려움 | 보통 |
| **실무 사용** | 정적 쿼리 | 거의 안 씀 | **대부분** |

### 💡 BooleanBuilder의 한계

현재 방식의 문제점:
```java
BooleanBuilder builder = new BooleanBuilder();
if (keyword != null) {
    builder.and(comment.content.contains(keyword));
}
if (postId != null) {
    builder.and(comment.post.id.eq(postId));
}
```

**한계**:
- 조건 재사용 불가능
- 테스트 어려움
- 복잡한 조건 조합 시 가독성 저하

**해결책**: **BooleanExpression 패턴** (다음 문서!)

### QueryDSL Advanced (04.querydsl-advanced.md)
- **BooleanExpression 패턴**: 조건 재사용 및 조합
- **복잡한 동적 쿼리**: 다중 조건 처리
- **통계 쿼리**: 집계, 서브쿼리
- **실무 패턴**: 실제 프로젝트에서 사용하는 방식

**미리보기**:
```java
// ✅ 조건을 메서드로 분리 → 재사용 가능!
private BooleanExpression contentContains(String keyword) {
    return keyword != null ? comment.content.contains(keyword) : null;
}

private BooleanExpression postIdEq(Long postId) {
    return postId != null ? comment.post.id.eq(postId) : null;
}

// 조합해서 사용
List<Comment> results = queryFactory
    .selectFrom(comment)
    .where(
        contentContains(keyword),
        postIdEq(postId)
    )
    .fetch();
```

**장점**:
- 조건 메서드 재사용 → 중복 제거
- 테스트 가능 (단위 테스트)
- null 처리 자동 (null 반환 시 조건 무시)
- 가독성 극대화

이제 실무 핵심 패턴을 배워봅시다! 🚀
