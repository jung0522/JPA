# Criteria API

## 이론

### 기본 개념
- **Criteria API**: JPA 표준 스펙의 동적 쿼리 API
- **특징**: 프로그래밍 방식으로 쿼리 작성
- **목적**: JPQL의 동적 쿼리 한계 해결
- **타입 안정성**: 일부 확보 (하지만 완전하지 않음)

### JPQL vs Criteria

**JPQL (문자열)**:
```java
@Query("SELECT c FROM Comment c WHERE c.content LIKE %:keyword%")
List<Comment> findByKeyword(@Param("keyword") String keyword);
```

**Criteria (프로그래밍)**:
```java
CriteriaBuilder cb = em.getCriteriaBuilder();
CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
Root<Comment> root = query.from(Comment.class);
query.where(cb.like(root.get("content"), "%" + keyword + "%"));
return em.createQuery(query).getResultList();
```

## Criteria 기본 구조

### 핵심 구성 요소

```java
// 1. CriteriaBuilder: 쿼리 빌더
CriteriaBuilder cb = em.getCriteriaBuilder();

// 2. CriteriaQuery: 쿼리 정의
CriteriaQuery<Comment> query = cb.createQuery(Comment.class);

// 3. Root: FROM 절 (엔티티)
Root<Comment> root = query.from(Comment.class);

// 4. Predicate: WHERE 조건
Predicate predicate = cb.equal(root.get("id"), 1L);

// 5. 쿼리 실행
query.where(predicate);
List<Comment> results = em.createQuery(query).getResultList();
```

## Criteria 기본 쿼리

### 1. 단순 조회

```java
@Repository
public class CommentCriteriaRepository {

    @PersistenceContext
    private EntityManager em;

    // 전체 조회
    public List<Comment> findAll() {
        CriteriaBuilder cb = em.getCriteriaBuilder();
        CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
        Root<Comment> root = query.from(Comment.class);

        return em.createQuery(query).getResultList();
    }

    // 조건 조회 (단일)
    public List<Comment> findByPostId(Long postId) {
        CriteriaBuilder cb = em.getCriteriaBuilder();
        CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
        Root<Comment> root = query.from(Comment.class);

        // WHERE c.post.id = :postId
        query.where(cb.equal(root.get("post").get("id"), postId));

        return em.createQuery(query).getResultList();
    }

    // LIKE 검색
    public List<Comment> findByKeyword(String keyword) {
        CriteriaBuilder cb = em.getCriteriaBuilder();
        CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
        Root<Comment> root = query.from(Comment.class);

        // WHERE c.content LIKE '%keyword%'
        query.where(cb.like(root.get("content"), "%" + keyword + "%"));

        return em.createQuery(query).getResultList();
    }
}
```

### 2. 동적 쿼리 (핵심!)

```java
public List<Comment> searchComments(CommentSearchCondition condition) {
    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
    Root<Comment> root = query.from(Comment.class);

    // 조건을 담을 리스트
    List<Predicate> predicates = new ArrayList<>();

    // 키워드가 있으면 추가
    if (condition.getKeyword() != null) {
        predicates.add(cb.like(root.get("content"), "%" + condition.getKeyword() + "%"));
    }

    // postId가 있으면 추가
    if (condition.getPostId() != null) {
        predicates.add(cb.equal(root.get("post").get("id"), condition.getPostId()));
    }

    // 작성일 범위가 있으면 추가
    if (condition.getStartDate() != null) {
        predicates.add(cb.greaterThanOrEqualTo(root.get("createdAt"), condition.getStartDate()));
    }
    if (condition.getEndDate() != null) {
        predicates.add(cb.lessThanOrEqualTo(root.get("createdAt"), condition.getEndDate()));
    }

    // 조건 조합 (AND)
    query.where(predicates.toArray(new Predicate[0]));

    // 정렬
    query.orderBy(cb.desc(root.get("id")));

    return em.createQuery(query).getResultList();
}
```

### 3. Join 쿼리

```java
// 일반 Join
public List<Comment> findWithJoin() {
    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
    Root<Comment> comment = query.from(Comment.class);

    // JOIN
    Join<Comment, Post> post = comment.join("post", JoinType.INNER);

    // WHERE p.title LIKE '%키워드%'
    query.where(cb.like(post.get("title"), "%키워드%"));

    return em.createQuery(query).getResultList();
}

// Fetch Join
public List<Comment> findWithFetchJoin() {
    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
    Root<Comment> comment = query.from(Comment.class);

    // FETCH JOIN
    comment.fetch("post", JoinType.INNER);

    return em.createQuery(query).getResultList();
}
```

### 4. 집계 쿼리

```java
// COUNT
public Long countByPostId(Long postId) {
    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<Long> query = cb.createQuery(Long.class);
    Root<Comment> root = query.from(Comment.class);

    // SELECT COUNT(c)
    query.select(cb.count(root));
    query.where(cb.equal(root.get("post").get("id"), postId));

    return em.createQuery(query).getSingleResult();
}

// GROUP BY
public List<Object[]> countByPost() {
    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<Object[]> query = cb.createQuery(Object[].class);
    Root<Comment> comment = query.from(Comment.class);
    Join<Comment, Post> post = comment.join("post");

    // SELECT p.id, p.title, COUNT(c)
    query.multiselect(
        post.get("id"),
        post.get("title"),
        cb.count(comment)
    );

    // GROUP BY p.id, p.title
    query.groupBy(post.get("id"), post.get("title"));

    return em.createQuery(query).getResultList();
}
```

### 5. Predicate 조합

```java
// AND 조합
Predicate keyword = cb.like(root.get("content"), "%키워드%");
Predicate postId = cb.equal(root.get("post").get("id"), 1L);
query.where(cb.and(keyword, postId));

// OR 조합
Predicate condition1 = cb.like(root.get("content"), "%A%");
Predicate condition2 = cb.like(root.get("content"), "%B%");
query.where(cb.or(condition1, condition2));

// NOT
Predicate isActive = cb.equal(root.get("status"), "ACTIVE");
query.where(cb.not(isActive));

// 복합 조합
Predicate complexCondition = cb.and(
    cb.or(
        cb.like(root.get("content"), "%A%"),
        cb.like(root.get("content"), "%B%")
    ),
    cb.equal(root.get("post").get("id"), 1L)
);
query.where(complexCondition);
```

## API 엔드포인트

```java
@RestController
@RequestMapping("/api/criteria/comments")
@RequiredArgsConstructor
public class CommentCriteriaController {

    private final CommentCriteriaService service;

    // 동적 검색
    @GetMapping("/search")
    public ResponseEntity<List<CommentResponse>> search(
        @RequestParam(required = false) String keyword,
        @RequestParam(required = false) Long postId,
        @RequestParam(required = false) @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate startDate,
        @RequestParam(required = false) @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate endDate
    ) {
        CommentSearchCondition condition = new CommentSearchCondition();
        condition.setKeyword(keyword);
        condition.setPostId(postId);
        if (startDate != null) condition.setStartDate(startDate.atStartOfDay());
        if (endDate != null) condition.setEndDate(endDate.atTime(23, 59, 59));

        return ResponseEntity.ok(service.searchComments(condition));
    }

    // 통계
    @GetMapping("/stats/by-post")
    public ResponseEntity<List<CommentStatDto>> getStatsByPost() {
        return ResponseEntity.ok(service.countByPost());
    }
}
```

## 실습 시나리오

### 1. 동적 검색 테스트 (10분)

**테스트 케이스**:
```bash
# 1. 키워드만
GET /api/criteria/comments/search?keyword=테스트

# 2. postId만
GET /api/criteria/comments/search?postId=1

# 3. 키워드 + postId
GET /api/criteria/comments/search?keyword=테스트&postId=1

# 4. 작성일 범위
GET /api/criteria/comments/search?startDate=2024-01-01&endDate=2024-12-31

# 5. 모든 조건
GET /api/criteria/comments/search?keyword=테스트&postId=1&startDate=2024-01-01&endDate=2024-12-31
```

**확인사항**:
- 각 조건에 따라 WHERE 절이 동적으로 생성
- SQL Injection 걱정 없음 (파라미터 바인딩)
- 조합 폭발 문제 해결

---

### 2. JPQL vs Criteria 비교 (5분)

**동일 요구사항 구현**:
```java
// JPQL - 모든 경우의 수 작성 필요
findByKeyword()
findByPostId()
findByKeywordAndPostId()
// ... 8개 메서드

// Criteria - 하나의 메서드로 해결
searchComments(condition)  // 모든 조합 처리!
```

**확인사항**:
- Criteria의 장점: 동적 쿼리 작성 가능
- 코드 중복 제거

## Criteria의 장점과 한계

### ✅ 장점

1. **동적 쿼리 작성 가능**
   - Predicate 리스트로 조건 조합
   - 조합 폭발 문제 해결

2. **SQL Injection 방지**
   - 파라미터 바인딩 자동 처리
   - 문자열 조합 없음

3. **JPA 표준 스펙**
   - 별도 라이브러리 불필요
   - 모든 JPA 구현체에서 사용 가능

---

### ❌ 한계

1. **가독성 나쁨** (치명적!)
   ```java
   // 😭 이게 뭐하는 코드인지...
   query.where(
       cb.and(
           cb.or(
               cb.like(root.get("content"), "%A%"),
               cb.like(root.get("content"), "%B%")
           ),
           cb.equal(root.get("post").get("id"), 1L)
       )
   );
   ```

2. **타입 안정성 불완전**
   ```java
   root.get("content")  // ❌ 여전히 문자열! 오타 가능!
   root.get("conten")   // 컴파일은 되지만 런타임 에러
   ```

3. **코드 장황함**
   ```java
   // 단순 조회인데 7줄...
   CriteriaBuilder cb = em.getCriteriaBuilder();
   CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
   Root<Comment> root = query.from(Comment.class);
   query.where(cb.equal(root.get("id"), 1L));
   return em.createQuery(query).getResultList();

   // JPQL은 1줄
   return em.createQuery("SELECT c FROM Comment c WHERE c.id = 1", Comment.class).getResultList();
   ```

4. **학습 곡선 높음**
   - 개념이 복잡함
   - 실무에서 거의 사용 안 함

5. **IDE 지원 부족**
   - 자동완성 제한적
   - 리팩터링 어려움

## 핵심 정리

### 📊 JPQL vs Criteria 비교

| 구분 | JPQL | Criteria |
|------|------|----------|
| **가독성** | ✅ 좋음 | ❌ 나쁨 |
| **동적 쿼리** | ❌ 불가능 | ✅ 가능 |
| **타입 안정성** | ❌ 없음 | △ 일부 |
| **코드 길이** | ✅ 짧음 | ❌ 김 |
| **학습 난이도** | ✅ 쉬움 | ❌ 어려움 |
| **실무 사용** | 정적 쿼리 | 거의 안 씀 |

### 💡 Criteria를 배우는 이유

"실무에서 안 쓰는데 왜 배우나?"

→ **QueryDSL의 가치를 이해하기 위해!**

- Criteria의 장점 (동적 쿼리)
- Criteria의 단점 (가독성, 타입 안정성)
- 이 두 가지를 모두 해결한 것이 **QueryDSL**

## 다음 단계

### QueryDSL로 완벽한 해결 (03.querydsl-basic.md)
- 가독성 좋음 (SQL과 유사)
- 완전한 타입 안정성 (컴파일 타임 체크)
- 동적 쿼리 쉬움 (BooleanBuilder)
- IDE 지원 완벽 (자동완성, 리팩터링)

**미리보기**:
```java
// QueryDSL - 간결하고 직관적!
QComment comment = QComment.comment;

BooleanBuilder builder = new BooleanBuilder();
if (keyword != null) {
    builder.and(comment.content.contains(keyword));  // 타입 안전!
}
if (postId != null) {
    builder.and(comment.post.id.eq(postId));
}

List<Comment> results = queryFactory
    .selectFrom(comment)
    .where(builder)
    .fetch();
```

**Criteria vs QueryDSL**:
- Criteria: `root.get("content")` (문자열 - 오타 위험)
- QueryDSL: `comment.content` (타입 안전 - 오타 불가능!)

이제 QueryDSL로 넘어가서 진짜 해답을 찾아봅시다! 🚀
