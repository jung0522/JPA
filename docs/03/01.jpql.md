# JPQL (Java Persistence Query Language)

## 이론

### 기본 개념
- **JPQL**: 객체 지향 쿼리 언어
- **특징**: SQL과 유사하지만 엔티티 객체 대상
- **장점**: 데이터베이스 독립적
- **단점**: 문자열 기반 → 타입 안정성 없음, 오타 런타임 발견

### JPQL vs SQL

```java
// SQL (테이블 대상)
SELECT * FROM comments_m2one WHERE post_id = 1;

// JPQL (엔티티 대상)
SELECT c FROM Comment c WHERE c.post.id = 1;
```

**차이점**:
- SQL: 테이블명, 컬럼명 사용
- JPQL: 엔티티명, 필드명 사용
- JPQL: 연관관계 탐색 가능 (`c.post.id`)

## JPQL 기본 쿼리

### 1. 단순 조회

```java
@Repository
public interface CommentJpqlRepository extends JpaRepository<Comment, Long> {

    // 기본 조회
    @Query("SELECT c FROM Comment c")
    List<Comment> findAllJpql();

    // WHERE 조건
    @Query("SELECT c FROM Comment c WHERE c.post.id = :postId")
    List<Comment> findByPostIdJpql(@Param("postId") Long postId);

    // LIKE 검색
    @Query("SELECT c FROM Comment c WHERE c.content LIKE %:keyword%")
    List<Comment> findByContentContainingJpql(@Param("keyword") String keyword);
}
```

**생성되는 SQL**:
```sql
-- findAllJpql()
SELECT c.id, c.content, c.post_id FROM comments_m2one c;

-- findByPostIdJpql(1L)
SELECT c.id, c.content, c.post_id FROM comments_m2one c WHERE c.post_id = 1;

-- findByContentContainingJpql("테스트")
SELECT c.id, c.content, c.post_id FROM comments_m2one c WHERE c.content LIKE '%테스트%';
```

---

### 2. Join 쿼리

```java
// 일반 Join (N+1 발생)
@Query("SELECT c FROM Comment c JOIN c.post p WHERE p.title LIKE %:title%")
List<Comment> findByPostTitleJpql(@Param("title") String title);

// Fetch Join (N+1 해결)
@Query("SELECT c FROM Comment c JOIN FETCH c.post")
List<Comment> findAllWithPostJpql();

// 조건 + Fetch Join
@Query("SELECT c FROM Comment c JOIN FETCH c.post p WHERE p.id = :postId")
List<Comment> findByPostIdWithFetchJpql(@Param("postId") Long postId);
```

**생성되는 SQL**:
```sql
-- 일반 Join
SELECT c.* FROM comments_m2one c
INNER JOIN posts_m2one p ON c.post_id = p.id
WHERE p.title LIKE '%키워드%';

-- Fetch Join
SELECT c.*, p.* FROM comments_m2one c
INNER JOIN posts_m2one p ON c.post_id = p.id;
```

---

### 3. 집계 함수

```java
// 카운트
@Query("SELECT COUNT(c) FROM Comment c WHERE c.post.id = :postId")
Long countByPostIdJpql(@Param("postId") Long postId);

// 게시글별 댓글 수
@Query("""
    SELECT p.id, p.title, COUNT(c)
    FROM Comment c
    JOIN c.post p
    GROUP BY p.id, p.title
    """)
List<Object[]> countByPostJpql();

// DTO 프로젝션
@Query("""
    SELECT new io.goorm.jpa.jpql.dto.CommentStatDto(
        p.id,
        p.title,
        COUNT(c)
    )
    FROM Comment c
    JOIN c.post p
    GROUP BY p.id, p.title
    """)
List<CommentStatDto> countByPostWithDtoJpql();
```

**DTO 정의**:
```java
public record CommentStatDto(
    Long postId,
    String postTitle,
    Long commentCount
) {}
```

### 4. 서브쿼리

```java
// 댓글 많은 게시글 조회
@Query("""
    SELECT c FROM Comment c
    WHERE c.post.id IN (
        SELECT c2.post.id
        FROM Comment c2
        GROUP BY c2.post.id
        HAVING COUNT(c2) >= :minCount
    )
    """)
List<Comment> findCommentsInPopularPostsJpql(@Param("minCount") Long minCount);

// 최신 댓글이 있는 게시글
@Query("""
    SELECT c FROM Comment c
    WHERE c.id IN (
        SELECT MAX(c2.id)
        FROM Comment c2
        GROUP BY c2.post.id
    )
    """)
List<Comment> findLatestCommentsJpql();
```

## 동적 쿼리의 한계

### 문제 상황

실무에서 자주 마주치는 요구사항:
- 키워드 입력 시에만 검색
- 게시글 ID가 있을 때만 필터링
- 작성일 범위가 있을 때만 기간 필터

**안티패턴 1: 문자열 조합**
```java
public List<Comment> searchComments(String keyword, Long postId) {
    String jpql = "SELECT c FROM Comment c WHERE 1=1 ";

    if (keyword != null) {
        jpql += "AND c.content LIKE '%" + keyword + "%' ";  // ❌ SQL Injection 위험!
    }
    if (postId != null) {
        jpql += "AND c.post.id = " + postId + " ";
    }

    return em.createQuery(jpql, Comment.class).getResultList();
}
```

**문제점**:
1. **SQL Injection 위험**: 사용자 입력을 직접 문자열에 추가
2. **타입 안정성 없음**: 오타 발견 불가 (`c.conten` → 런타임 에러)
3. **가독성 나쁨**: 조건이 많아질수록 복잡도 증가
4. **유지보수 어려움**: 조건 변경 시 문자열 전체 수정

**안티패턴 2: 모든 경우의 수 쿼리 작성**
```java
@Query("SELECT c FROM Comment c WHERE c.content LIKE %:keyword%")
List<Comment> findByKeyword(@Param("keyword") String keyword);

@Query("SELECT c FROM Comment c WHERE c.post.id = :postId")
List<Comment> findByPostId(@Param("postId") Long postId);

@Query("SELECT c FROM Comment c WHERE c.content LIKE %:keyword% AND c.post.id = :postId")
List<Comment> findByKeywordAndPostId(@Param("keyword") String keyword, @Param("postId") Long postId);

// 조건 3개, 4개... 조합 폭발! 😱
```

**문제점**:
- 조건 3개만 되어도 2^3 = 8개의 메서드 필요
- 중복 코드 증가
- 유지보수 불가능

## API 엔드포인트

### 기본 CRUD

```java
@RestController
@RequestMapping("/api/jpql/comments")
@RequiredArgsConstructor
public class CommentJpqlController {

    private final CommentJpqlService service;

    // 전체 조회
    @GetMapping
    public ResponseEntity<List<CommentResponse>> getComments() {
        return ResponseEntity.ok(service.findAll());
    }

    // 게시글별 조회
    @GetMapping("/posts/{postId}")
    public ResponseEntity<List<CommentResponse>> getByPost(@PathVariable Long postId) {
        return ResponseEntity.ok(service.findByPostId(postId));
    }

    // 키워드 검색
    @GetMapping("/search")
    public ResponseEntity<List<CommentResponse>> search(@RequestParam String keyword) {
        return ResponseEntity.ok(service.findByKeyword(keyword));
    }
}
```

## 핵심 정리

### ✅ JPQL의 장점
- SQL과 유사한 직관적 문법
- 데이터베이스 독립적
- 정적 쿼리 작성에 적합
- Spring Data JPA `@Query`로 간편 사용

### ❌ JPQL의 한계
- **타입 안정성 없음**: 오타 런타임 발견
- **동적 쿼리 작성 어려움**: 문자열 조합 필요
- **SQL Injection 위험**: 파라미터 바인딩 필수
- **IDE 지원 부족**: 자동완성 없음
- **리팩터링 어려움**: 필드명 변경 시 문자열 수동 수정

### 💡 언제 사용하나?
- **정적 쿼리**: 조건이 고정된 간단한 조회
- **Repository 메서드**: `@Query` 어노테이션
- **학습 목적**: JPA의 기본 개념 이해

## 다음 단계

### Criteria API로 해결 (02.criteria.md)
- 동적 쿼리를 타입 안전하게 작성
- Predicate 조합으로 조건 처리
- 문자열 조합 없이 프로그래밍 방식으로 쿼리 구성

**미리보기**:
```java
// Criteria로 동적 쿼리 작성
CriteriaBuilder cb = em.getCriteriaBuilder();
CriteriaQuery<Comment> query = cb.createQuery(Comment.class);
Root<Comment> root = query.from(Comment.class);

List<Predicate> predicates = new ArrayList<>();
if (keyword != null) {
    predicates.add(cb.like(root.get("content"), "%" + keyword + "%"));
}
if (postId != null) {
    predicates.add(cb.equal(root.get("post").get("id"), postId));
}
query.where(predicates.toArray(new Predicate[0]));
```
