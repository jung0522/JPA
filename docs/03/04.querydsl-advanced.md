# QueryDSL Advanced: BooleanExpression 패턴

## 이론

### BooleanBuilder의 한계

**현재 방식 (BooleanBuilder)**:
```java
public List<Comment> searchComments(CommentSearchCondition condition) {
    BooleanBuilder builder = new BooleanBuilder();

    if (condition.getKeyword() != null) {
        builder.and(comment.content.contains(condition.getKeyword()));
    }
    if (condition.getPostId() != null) {
        builder.and(comment.post.id.eq(condition.getPostId()));
    }
    if (condition.getStartDate() != null) {
        builder.and(comment.createdAt.goe(condition.getStartDate()));
    }
    // ... 조건이 많아질수록 복잡해짐

    return queryFactory
        .selectFrom(comment)
        .where(builder)
        .fetch();
}
```

**문제점**:
1. **재사용 불가능**: 다른 메서드에서 동일 조건 사용 시 중복 코드
2. **테스트 어려움**: 조건 로직을 개별적으로 테스트 불가
3. **가독성 저하**: 조건이 많아지면 메서드가 길어짐
4. **유지보수 어려움**: 조건 수정 시 여러 곳 수정 필요

---

### BooleanExpression 패턴

**개선된 방식 (BooleanExpression)**:
```java
public List<Comment> searchComments(CommentSearchCondition condition) {
    return queryFactory
        .selectFrom(comment)
        .where(
            contentContains(condition.getKeyword()),
            postIdEq(condition.getPostId()),
            createdBetween(condition.getStartDate(), condition.getEndDate())
        )
        .fetch();
}

// 조건을 메서드로 분리 → 재사용 가능!
private BooleanExpression contentContains(String keyword) {
    return keyword != null ? comment.content.contains(keyword) : null;
}

private BooleanExpression postIdEq(Long postId) {
    return postId != null ? comment.post.id.eq(postId) : null;
}

private BooleanExpression createdBetween(LocalDateTime start, LocalDateTime end) {
    if (start == null && end == null) return null;
    if (start == null) return comment.createdAt.loe(end);
    if (end == null) return comment.createdAt.goe(start);
    return comment.createdAt.between(start, end);
}
```

**장점**:
1. **재사용 가능**: 다른 메서드에서도 동일 조건 사용 가능
2. **테스트 가능**: 각 조건 메서드를 개별적으로 테스트
3. **가독성**: 메서드명으로 의도 명확히 표현
4. **null 처리 자동**: null 반환 시 QueryDSL이 조건 무시
5. **조합 가능**: 여러 조건을 and/or로 조합

### 3. 조건 조합 (AND, OR)

```java
// AND 조합
private BooleanExpression keywordCondition(String keyword) {
    // 키워드가 content 또는 제목에 포함
    return keyword != null
        ? comment.content.contains(keyword)
            .or(comment.post.title.contains(keyword))
        : null;
}

// 복잡한 조합
private BooleanExpression searchCondition(String keyword, Long postId) {
    if (keyword == null && postId == null) return null;

    BooleanExpression result = null;

    if (keyword != null) {
        result = comment.content.contains(keyword);
    }

    if (postId != null) {
        BooleanExpression postCondition = comment.post.id.eq(postId);
        result = (result == null) ? postCondition : result.and(postCondition);
    }

    return result;
}

// 더 깔끔한 방법: null 처리를 QueryDSL에 맡기기
public List<Comment> searchAdvanced(String keyword, Long postId) {
    return queryFactory
        .selectFrom(comment)
        .where(
            contentContains(keyword),
            postIdEq(postId)
            // null이면 자동으로 무시됨!
        )
        .fetch();
}
```

### 1. 복잡한 검색 조건

```java
@Getter @Setter
public class CommentSearchCondition {
    private String keyword;           // 키워드 검색
    private Long postId;              // 게시글 필터
    private LocalDate startDate;      // 작성일 시작
    private LocalDate endDate;        // 작성일 종료
    private String status;            // 상태 (ACTIVE, DELETED)
    private Long minLikes;            // 최소 좋아요 수
    private List<Long> authorIds;     // 작성자 ID 목록
}

@Repository
@RequiredArgsConstructor
public class CommentAdvancedRepositoryImpl implements CommentAdvancedRepository {

    private final JPAQueryFactory queryFactory;

    public Page<CommentDto> searchComments(CommentSearchCondition condition, Pageable pageable) {
        QComment comment = QComment.comment;
        QPost post = QPost.post;

        // DTO 프로젝션 (@QueryProjection 사용)
        List<CommentDto> content = queryFactory
            .select(new QCommentDto(
                comment.id,
                comment.content,
                post.title,
                comment.createdAt
            ))
            .from(comment)
            .join(comment.post, post)
            .where(
                keywordInContentOrTitle(condition.getKeyword()),
                postIdEq(condition.getPostId()),
                createdBetween(toDateTime(condition.getStartDate()), toDateTime(condition.getEndDate())),
                statusEq(condition.getStatus()),
                likesGoe(condition.getMinLikes()),
                authorIdIn(condition.getAuthorIds())
            )
            .offset(pageable.getOffset())
            .limit(pageable.getPageSize())
            .orderBy(getOrderSpecifiers(pageable.getSort()))
            .fetch();

        // 카운트 쿼리 최적화 (조인 필요 없으면 제거)
        Long total = queryFactory
            .select(comment.count())
            .from(comment)
            .where(
                contentContains(condition.getKeyword()),
                postIdEq(condition.getPostId()),
                createdBetween(toDateTime(condition.getStartDate()), toDateTime(condition.getEndDate())),
                statusEq(condition.getStatus()),
                likesGoe(condition.getMinLikes()),
                authorIdIn(condition.getAuthorIds())
            )
            .fetchOne();

        return new PageImpl<>(content, pageable, total);
    }

    // 조건 메서드들
    private BooleanExpression keywordInContentOrTitle(String keyword) {
        return keyword != null
            ? comment.content.contains(keyword)
                .or(comment.post.title.contains(keyword))
            : null;
    }

    private BooleanExpression contentContains(String keyword) {
        return keyword != null ? comment.content.contains(keyword) : null;
    }

    private BooleanExpression postIdEq(Long postId) {
        return postId != null ? comment.post.id.eq(postId) : null;
    }

    private BooleanExpression createdBetween(LocalDateTime start, LocalDateTime end) {
        if (start == null && end == null) return null;
        if (start == null) return comment.createdAt.loe(end);
        if (end == null) return comment.createdAt.goe(start);
        return comment.createdAt.between(start, end);
    }

    private BooleanExpression statusEq(String status) {
        return status != null ? comment.status.eq(status) : null;
    }

    private BooleanExpression likesGoe(Long minLikes) {
        return minLikes != null ? comment.likes.goe(minLikes) : null;
    }

    private BooleanExpression authorIdIn(List<Long> authorIds) {
        return (authorIds != null && !authorIds.isEmpty())
            ? comment.author.id.in(authorIds)
            : null;
    }

    // 동적 정렬
    private OrderSpecifier<?>[] getOrderSpecifiers(Sort sort) {
        return sort.stream()
            .map(order -> {
                Order direction = order.isAscending() ? Order.ASC : Order.DESC;
                String property = order.getProperty();

                return switch (property) {
                    case "id" -> new OrderSpecifier<>(direction, comment.id);
                    case "createdAt" -> new OrderSpecifier<>(direction, comment.createdAt);
                    case "likes" -> new OrderSpecifier<>(direction, comment.likes);
                    default -> new OrderSpecifier<>(direction, comment.id);
                };
            })
            .toArray(OrderSpecifier[]::new);
    }

    // 날짜 변환 헬퍼
    private LocalDateTime toDateTime(LocalDate date) {
        return date != null ? date.atStartOfDay() : null;
    }
}
```

```java
// 게시글별 댓글 통계
public List<CommentStatDto> getCommentStatsByPost() {
    QComment comment = QComment.comment;
    QPost post = QPost.post;

    return queryFactory
        .select(new QCommentStatDto(
            post.id,
            post.title,
            comment.count(),
            comment.likes.sum(),
            comment.likes.avg()
        ))
        .from(comment)
        .join(comment.post, post)
        .groupBy(post.id, post.title)
        .orderBy(comment.count().desc())
        .fetch();
}

// 일별 댓글 통계
public List<DailyCommentStatDto> getDailyStats(LocalDate startDate, LocalDate endDate) {
    QComment comment = QComment.comment;

    return queryFactory
        .select(new QDailyCommentStatDto(
            comment.createdAt.as("date"),
            comment.count()
        ))
        .from(comment)
        .where(
            createdBetween(
                startDate.atStartOfDay(),
                endDate.atTime(23, 59, 59)
            )
        )
        .groupBy(comment.createdAt.year(), comment.createdAt.month(), comment.createdAt.dayOfMonth())
        .orderBy(comment.createdAt.asc())
        .fetch();
}

// 인기 게시글 TOP 10
public List<PostWithCommentCountDto> getTop10Posts() {
    QComment comment = QComment.comment;
    QPost post = QPost.post;

    return queryFactory
        .select(new QPostWithCommentCountDto(
            post.id,
            post.title,
            comment.count()
        ))
        .from(comment)
        .join(comment.post, post)
        .groupBy(post.id, post.title)
        .orderBy(comment.count().desc())
        .limit(10)
        .fetch();
}
```

```java
// 댓글 많은 게시글의 댓글 조회
public List<Comment> findCommentsInPopularPosts(Long minCommentCount) {
    QComment comment = QComment.comment;
    QComment commentSub = new QComment("commentSub");

    return queryFactory
        .selectFrom(comment)
        .where(comment.post.id.in(
            JPAExpressions
                .select(commentSub.post.id)
                .from(commentSub)
                .groupBy(commentSub.post.id)
                .having(commentSub.count().goe(minCommentCount))
        ))
        .fetch();
}

// 각 게시글의 최신 댓글만 조회
public List<Comment> findLatestCommentsByPost() {
    QComment comment = QComment.comment;
    QComment commentSub = new QComment("commentSub");

    return queryFactory
        .selectFrom(comment)
        .where(comment.id.in(
            JPAExpressions
                .select(commentSub.id.max())
                .from(commentSub)
                .groupBy(commentSub.post.id)
        ))
        .fetch();
}
```

### 4. BooleanBuilder vs BooleanExpression 비교 (5분)

**Before (BooleanBuilder)**:
```java
public List<Comment> search(String keyword, Long postId) {
    BooleanBuilder builder = new BooleanBuilder();
    if (keyword != null) {
        builder.and(comment.content.contains(keyword));
    }
    if (postId != null) {
        builder.and(comment.post.id.eq(postId));
    }
    return queryFactory.selectFrom(comment).where(builder).fetch();
}
```

**After (BooleanExpression)**:
```java
public List<Comment> search(String keyword, Long postId) {
    return queryFactory
        .selectFrom(comment)
        .where(
            contentContains(keyword),
            postIdEq(postId)
        )
        .fetch();
}

private BooleanExpression contentContains(String keyword) {
    return keyword != null ? comment.content.contains(keyword) : null;
}

private BooleanExpression postIdEq(Long postId) {
    return postId != null ? comment.post.id.eq(postId) : null;
}
```

**차이점**:
- 재사용: ❌ vs ✅
- 가독성: △ vs ✅
- 테스트: ❌ vs ✅

## 핵심 정리

### ✅ BooleanExpression 패턴의 장점

1. **재사용성**
   - 동일 조건을 여러 메서드에서 사용
   - DRY 원칙 준수

2. **테스트 가능**
   - 각 조건 메서드를 개별 테스트
   - 단위 테스트 작성 용이

3. **가독성**
   - 메서드명으로 의도 명확히 표현
   - 복잡한 조건도 간결하게 표현

4. **null 처리 자동**
   - null 반환 시 QueryDSL이 조건 무시
   - 별도 null 체크 불필요

5. **조합 가능**
   - and, or로 조건 조합
   - 복잡한 비즈니스 로직 표현

### 📊 실무 적용 체크리스트

- [ ] 모든 동적 조건을 BooleanExpression 메서드로 분리
- [ ] null 처리를 각 조건 메서드에서 담당
- [ ] 조건 메서드명은 의도를 명확히 표현 (contentContains, postIdEq)
- [ ] 복잡한 조건은 여러 BooleanExpression 조합
- [ ] 동일 조건은 재사용 (검색, 카운트, 통계 등)
- [ ] 페이징 시 카운트 쿼리 최적화 고려
- [ ] DTO 프로젝션으로 필요한 데이터만 조회

---

### 💡 실무 팁

1. **조건 메서드는 private으로**
   - 외부 노출 불필요
   - Repository 내부에서만 사용

2. **복잡한 조건은 별도 메서드로**

   ```java
   }
   ```

4. **카운트 쿼리 최적화**

## 🎉 완료!

이제 **QueryDSL의 모든 것**을 마스터했습니다!

**핵심 정리**:
1. JPQL: 정적 쿼리, 가독성
2. Criteria: 동적 쿼리, 가독성 나쁨
3. QueryDSL: 동적 쿼리 + 가독성 + 타입 안전
4. **BooleanExpression**: 재사용 + 테스트 + 실무 표준

**실무 적용**:
- 정적 쿼리: `@Query` (JPQL)
- 동적 쿼리: QueryDSL + BooleanExpression
- Criteria: 사용 안 함

이제 step04에서 양방향 관계를 배우고 JPA를 완전 정복합시다! 🚀
